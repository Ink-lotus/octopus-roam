## 1. 目标与最终决定

用户有便宜但不稳定的渠道 A，以及稳定但价格较高的渠道 B。当前故障转移到 B 后，只要 B 正常，就会持续使用 B。用户希望在确认 A 恢复后，直接在故障转移模式中手动切回 A，并继续享有自动故障转移。

典型流程：A 故障进入冷却 → 自动使用 B → A 自然结束冷却，或用户手动解除 A 的冷却 → 用户点击 A → 后续选路使用 A → A 再次达到失败阈值时自动选择备用成员。

以下决定已经完成确认，接手会话应据此实施：

| 项目 | 最终决定 |
| --- | --- |
| 操作范围 | 当前分组中的指定成员，使用分组 ID 和成员 ID 定位。一个成员对应具体渠道授权，可能包含特定模型和凭据。 |
| 模式 | 在故障转移模式内选择当前成员，后续失败仍按分组优先级自动转移。 |
| 冷却结束 | 自然冷却到期与人工解除效果一致：连续失败计数清零，相关失败退避解除，重新获得完整尝试预算。 |
| 失败计数覆盖 | 保留现有范围，包括连接失败、超时、非流式上游失败及流式中断，沿用现有真实失败判定。 |
| 请求中断 | 完全沿用现有手动模式各入口的行为，具体见第 3 节。 |
| 并发和过期操作 | 后端校验最新状态及版本，防止旧确认解除新一轮冷却、旧结果覆盖新状态。 |
| 恢复通知 | 计数清零、冷却结束和人工选中本身不产生成功恢复通知；真实请求完整成功且满足既有条件后才通知恢复。 |
| 保存期限 | 选择和冷却继续属于进程内运行态；页面刷新保留，服务重启或相关路由配置重置后按配置重新选路。 |

## 2. 界面与选路契约

### 2.1 成员点击行为

| 成员状态或操作 | 预期行为 |
| --- | --- |
| 未冷却且配置可用，点击其他成员 | 切换为当前成员。故障转移模式继续生效。 |
| 重复点击故障转移的当前成员 | 保持选中，不取消选择，不触发额外中断。 |
| 点击冷却中的成员 | 在成员行内展开确认区，显示剩余冷却时间和两个按钮。 |
| 点击“解除冷却” | 重置该成员本轮冷却及连续失败状态，收起确认区；提示“已解除冷却，可点击切换”。再次独立点击该成员才主动切换。 |
| 点击“保持冷却” | 收起确认区，使用原截止时间继续倒计时。 |
| 确认区展开期间自然到期 | 执行自然到期处理，收起确认区，恢复普通可点击状态；本次确认交互不能顺带触发选中。 |
| 成员被禁用、凭据不可用或成员被移除 | 根据最新配置禁止相关选择操作，展示原因或刷新列表。解除冷却也不能重新启用渠道、凭据或被删除的成员。 |

固定中文按钮文案为“解除冷却”“保持冷却”。确认区提示可采用：“解除冷却后，可再次点击此渠道进行切换。”成功提示采用：“已解除冷却，可点击切换。”

解除按钮的点击只执行解除操作，必须阻止事件冒泡。拖拽、移除成员和确认按钮也要与整行点击分开处理。请求提交期间显示进行中状态并防止重复操作；失败时以服务端最新状态恢复界面。键盘可以进入、操作和退出确认区，关闭后焦点有明确去向。

成员的“当前使用”标记只表示选路结果。冷却到期或解除后，界面表示重新允许尝试，成功恢复仍由真实请求验证。

### 2.2 解除后的选路

解除冷却这个操作本身不主动更换当前成员，也不额外发起上游测试请求。当前成员健康时继续使用它；用户再次点击已解除冷却的成员，才主动切换。

如果分组已经没有当前可用成员，真实请求正在等待恢复，解除冷却或自然到期应唤醒等待请求，按既有故障转移规则选择候选。此时该成员可以被自动选中，因此“解除”与“主动切换”分离并不阻止正常的自动选路。

成员顺序继续决定后续故障转移优先级。单次手动选择作为当前运行状态保存；该成员失败后，按配置顺序重新选择可用成员。健康的当前成员不会仅因另一成员结束冷却而被自动抢占。

### 2.3 失败计数和冷却结束

自然到期与人工解除必须调用同一套结束冷却逻辑，并满足：

1. 本成员共享连续失败计数归零，清除本轮失败产生的 `RetryNotBefore` 等等待限制。
2. 后续失败从 1 重新累计，相关指数退避从新一轮失败次数计算；同一入站请求再次尝试该成员时，请求内成员尝试预算也正确重开。
3. 同一轮冷却只执行一次重置，后续读取、重复请求和重复定时回调不会再次清零新产生的失败。
4. 历史请求、历史错误和累计用量、成功失败统计保留。共享保护计数与请求历史分别处理。
5. 普通重试间隔到期继续累计失败；只有完整成功或本节规定的冷却结束等有效状态转换才重置计数。不能在每次退避结束时清零，否则连续失败永远无法达到冷却阈值。
6. 冷却结束先于剩余退避计算。即使旧指数退避截止时间晚于冷却截止时间，自然冷却到期也应解除这轮旧等待。

示例：配置 `member_max_attempts = 2`，A 连续失败 2 次进入冷却。自然到期或人工解除后，A 的下一次真实失败计为 1，遵守本轮重试间隔；本轮再失败一次才重新冷却。配置阈值为 1 时，新的首次失败仍会触发冷却。

本次重置针对故障转移成员的冷却生命周期。手动模式继续采用其现有重试、失败计数和告警规则。

## 3. 请求中断契约

用户已经选择完全沿用当前手动模式各入口的行为。以下表格是实施和验收依据：

| 入口与请求状态 | 故障转移中手动选择新成员后的行为 |
| --- | --- |
| 分组卡片选择成员 | 更新当前成员并通知等待选路的请求；已经发出的上游请求继续执行。 |
| 日志详情，当前日志所对应的请求正在等待上游响应 | 先成功更新当前成员，再按该请求 ID 和原轮次调用现有轮次中断操作；该请求随后重新选路。 |
| 日志详情，流式响应已经开始输出 | 流继续执行，不调用用于等待响应轮次的中断操作，也不重放已提交响应。 |
| 目标请求轮次已经结束或发生变化 | 沿用现有轮次校验；中断旧轮次不影响新轮次。 |
| 仅解除冷却、保持冷却、重复点击当前成员或切换失败 | 不产生额外的请求中断。 |

实现入口是 `useStopRequest` 携带 `requestId` 和 `round`，对应后端 `Interrupt`。完整请求取消由 `CancelRequest` 提供，含义不同。本功能的选路操作继续采用上述按入口和轮次处理的方式。

人工中断、客户端取消和未发送的尝试继续沿用现有失败判定，不能作为新的上游真实失败计入共享计数。中断会异步完成，因此仍需保留版本、轮次、探测持有者和容量释放方面的必要校验。

## 5. 后端实施设计

### 5.1 统一结束冷却

在 Relay 内提取由 `routeMu` 保护的成员冷却结束操作，自然到期和人工解除共用。操作定位到一个分组成员和一轮冷却，保留其他成员的故障信息及当前选择。

自然到期需要由运行态的到期处理触发；选路、准入、结果结算和状态快照读取处补做基于当前时间的过期处理，保证调度延迟时仍遵守截止时间。特别要覆盖“B 持续健康、A 冷却到期”的情况：到期处理必须发生在当前成员健康的提前返回路径之外。

到期调度的具体组织可结合现有生命周期选择，例如维护分组最早到期任务。调度回调应验证分组运行态身份和冷却版本；分组删除、配置重置、备份导入或新冷却轮次产生后，旧回调不能修改新状态。测试应主要使用现有 `...At` 风格或可控时间驱动验证截止条件，避免依靠长时间睡眠。

结束冷却后发布最新状态，并唤醒等待冷却、退避或重新选路的请求。渠道并发额度和实际发送前的配置复核继续生效。

### 5.2 清零与恢复验证分别处理

当前实现会通过 `FailureStreak > 0` 判断恢复中的成员。加入到期清零后，需要让“仍待真实成功验证”的状态独立于这个计数，继续保留已有恢复探测互斥。恢复探测由真实业务请求承担，解除动作只修改状态。

计数清零后，新一轮失败和退避从头累计；完整成功才能确认恢复。取消、未发送、客户端写入失败等已有非上游故障路径应正常释放占用，等待状态不会消耗上游尝试预算或长期持有渠道容量。

上一轮冷却结束时，要推进能使旧尝试失效的成员周期标记。旧周期的迟到成功或失败仍可完成其请求记录，但不能重新设置本轮计数、退避或冷却。结果有效期与成功恢复标记需要明确区分，避免因推进周期而误发恢复通知。

### 5.3 手动选择当前成员

增加专门操作故障转移运行态的函数，在最新配置和同一临界区内验证成员后更新 `CurrentItemID`，使相关旧选路提交失效，并通知等待请求。首次人工选择可以建立该分组运行态。

现有持久化 `active_item_id` 在故障转移中被忽略，因此仅放开前端或只提交该字段无法完成本功能。选择与解除应采用运行态操作粒度，避免通过整组重置清掉其他成员的冷却、告警和健康信息。

已有请求的正常结果可以按其有效身份记入原成员状态；旧探测结果不能抢回已经人工切换的当前成员。当前选择版本、成员失败周期和恢复探测持有者分别校验，避免用一次普通选路变更清空整组失败计数。

### 5.4 接口和状态版本

建议增加两个独立的运行态接口，复用现有分组认证和响应风格：

| 操作 | 建议路径 | 参数语义 |
| --- | --- | --- |
| 选择成员 | `POST /api/v1/group/route/:id/select` | `item_id` 和预期运行态版本。 |
| 解除冷却 | `POST /api/v1/group/route/:id/release-cooldown` | `item_id` 和预期状态版本；版本必须能识别正在确认的冷却轮次。 |

路径、函数名和版本字段的具体编码可以遵循仓库风格。固定要求是：成功返回最新分组快照；后端检查模式、归属、成员状态及版本；版本失配或状态冲突返回 `409` 并使界面刷新；过期的选择操作不会隐式解除冷却。

重复操作必须保证不会再次清空新失败。目标已经自然到期时可以返回最新状态或冲突，但不能把一次过期确认变成切换操作。新一轮冷却开始后，旧确认不得解除它。

公开状态版本要支持同一运行态内的更新排序及运行态重建的区分。接口响应、普通读取和 SSE 共用版本规则。前端收到旧响应、旧事件或重连期间的旧快照时，保留更新的运行态。版本表示应避免 JavaScript 数字精度造成错误比较。

现有配置修改由 `groupMutationMu` 串行保护，运行态由 `routeMu` 保护。新操作应沿用一致的锁顺序；中断函数、网络发送和外部通知在适当的锁外执行，避免引入反向锁依赖。

### 5.5 通知

冷却结束时可以更新失效成员数量和界面快照，但不得制造真实成功记录、清空整个分组告警周期或伪造 `RecoveryVersion`。

恢复通知继续使用真实完整成功以及既有阈值条件。需要特别验证人工解除、自然到期和连续失败清零都不会借用较早的成功记录误发恢复；有效成功后的正常恢复通知仍能发出并去重。

## 6. 前端实施设计

分组卡片和日志详情共用“判断冷却状态、打开确认、解除冷却、调用故障转移选择接口”的逻辑，具体的请求中断保留在各自入口。切换接口成功后，日志详情才可能调用对应轮次的中断接口；卡片没有这个步骤。

冷却判断以最新运行态为依据，服务端再做最终校验。解除成功后只反馈解除结果；下一次独立的成员点击才调用选择接口。接口在途时，显示清晰的提交状态，以服务端快照确认最终选中成员。

行内确认需要覆盖点击、键盘、自然到期、成员失效、状态冲突和关闭后的焦点恢复。日志详情现有整行是 `button`，实现两个确认按钮时应调整结构，避免嵌套可交互按钮；保留可访问的名称、状态和键盘行为。

三份 locale 同步补齐按钮、提示、操作失败和状态变化文案。运行态的列表缓存、详情缓存及两个界面同步更新。SSE 重连时继续重新获取当前快照。

## 8. 验收矩阵与检查

| 编号 | 场景 | 必须验证的结果 |
| --- | --- | --- |
| A01 | B 为当前成员，用户点击未冷却的 A | 当前成员变为 A，分组保持故障转移；A 达阈值后能选备用。 |
| A02 | 点击当前成员 | 保持选中，预算、冷却和日志轮次不因重复点击改变。 |
| A03 | 点击冷却成员再选择“保持冷却” | 原截止时间、失败计数和当前成员保持原值。 |
| A04 | 人工解除 A 冷却 | A 的计数归零、旧失败退避解除；单次按钮操作没有顺带主动选中 A 或中断 B 的请求。 |
| A05 | B 持续健康时 A 自然到期 | A 完成与人工解除相同的重置，B 继续作为当前成员。 |
| A06 | 阈值为 2，结束冷却后再次失败 | 新周期先计 1，再次失败计 2 才冷却；指数退避从新周期计算。阈值为 1 时首次新失败即可冷却。 |
| A07 | 旧退避截止晚于冷却截止 | 自然到期和人工解除均清掉旧等待，成员重新获得尝试资格。 |
| A08 | 普通退避结束但尚未触发冷却 | 失败计数继续累计，可以正常达到冷却阈值。 |
| A09 | 同一请求等待冷却后再次选择同一成员 | 成员尝试预算重开，旧请求内计数不会使新周期提前结束。 |
| A10 | 多个请求同时在冷却结束后重试 | 保留恢复互斥与渠道并发限制，取消或未发送不会泄漏容量和探测资格。 |
| A11 | 冷却已结束，旧周期结果或定时回调迟到 | 不增加新周期失败数、不重设等待、不释放新探测、不抢回人工选择。有效的新周期失败仍正常累计。 |
| A12 | 旧确认、多次点击或多个页面并发操作 | 旧确认不能解除新一轮冷却；重复操作不能再次清零新失败。 |
| A13 | 接口响应、普通快照和 SSE 乱序或重连 | 列表与详情显示同一最新状态，旧状态不会覆盖新状态。 |
| A14 | 全部成员冷却，请求等待恢复 | 解除或自然到期唤醒请求并按规则选路；等待期间不空转、不占用发送额度。 |
| A15 | 分组卡片手动切换 | 已发出请求继续完成；等待选路的请求读取新选择。 |
| A16 | 日志详情切换，当前请求尚在等待响应 | 仅在切换成功后中断对应请求的原轮次，随后重新选路；过期轮次不影响新轮次。 |
| A17 | 日志详情切换，流已经开始输出 | 原流继续执行，已提交响应不重放。 |
| A18 | 同渠道在其他分组或对应其他成员 | 只更新被操作的成员，其他成员的故障记录与冷却不被重置。 |
| A19 | 禁用、删除、模式变更与操作并发 | 后端以最新配置校验，返回合理状态；旧操作和旧到期任务不会创建错误路由。 |
| A20 | 自然到期、人工解除或选中发生，尚无新成功 | 不发恢复成功通知；后续真实完整成功满足条件后正常通知并去重。 |
| A21 | 冷却确认期间到期、键盘操作、拖拽或点击子按钮 | 正确关闭和恢复焦点，无事件冒泡导致的额外选路，无嵌套按钮问题。 |
| A22 | 手动模式、非流式失败、连接失败、超时及取消 | 手动模式原有契约、原失败覆盖和非真实故障排除规则均通过回归。 |
| A23 | 服务重启、路由配置重置、分组删除或备份导入 | 运行态生命周期正确，旧回调和旧版本不能影响重建后的状态。 |
