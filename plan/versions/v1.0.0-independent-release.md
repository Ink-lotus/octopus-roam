# v1.0.0 首个独立稳定版

## 版本目标

把 `v0.1.0`～`v0.3.0` 的功能收口为可独立发布的产品版本，完成兼容检查、文档、主分支和发布标签。这个版本不等待生图、管理界面增强或 WebSocket。

## 进入条件

- `v0.1.0` 路由策略和隐私保护完成。
- `v0.2.0` 手动渠道刷新、分组同步、日志筛选和协议/禁用渠道管理完成。
- `v0.3.0` 自动同步和渠道并发限制完成。
- 工作区无未说明改动，现有 Go 和前端检查通过。

## 实现顺序

### V100-01 数据迁移与备份兼容审计

**实现内容**

- 列出所有新增设置、渠道字段、分组字段和匹配模式字段。
- 为旧数据库提供默认值，默认行为保持兼容。
- 确认旧备份版本可以导入，新备份包含新配置。
- 验证空模型渠道、空分组、失效分组成员和隐藏渠道不会破坏导入。
- 不删除已有旧迁移记录；新增迁移保持单调递增。

**预计材料**

- `internal/db/migrate/`
- `internal/model/backup.go`
- `internal/op/backup.go`
- `internal/model/setting.go`
- 渠道、分组模型和测试夹具

**验收**

- 从上游当前版本、阶段 4/5 备份和 `v0.x` 备份导入成功。
- 新版本导出的备份可以再次导入。
- 敏感字段不会因为备份导出泄露明文。

**验证**

- `go test ./internal/db/... ./internal/op ./internal/server/handlers -count=1`
- 旧备份导入、新备份导出和重复导入测试。

### V100-02 全量回归和构建

**验证内容**

- Relay 手动模式和故障转移模式。
- 路由默认值仅更新策略参数，不改变分组模式。
- 渠道模型刷新成功、空结果、Key 失败和事务回滚。
- 严格匹配和关键词匹配。
- 分组成员删除、追加和当前成员清理。
- 协议限制、禁用渠道隐藏和前端保存。
- 日志请求中置顶、筛选、取消和 SSE 重连。
- 全局自动更新、渠道退出、刷新锁和并发限制。
- Webhook 失败/恢复通知和脱敏。

**验证命令**

- `go test ./... -count=1`
- `go test -race ./internal/relay ./internal/server/handlers -count=1`
- `go vet ./...`
- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v100-build" --emptyOutDir false`
- `git diff --check`

### V100-03 文档与运行配置收口

**实现内容**

- 更新 README、中文 README、配置示例和升级说明。
- 记录新设置的默认值、空模型渠道行为、自动更新风险和回滚方式。
- 记录分组匹配模式、路由默认策略覆盖规则和日志状态定义。
- 增加故障排查章节：Key 失败、模型为空、并发排队、Webhook 失败。
- 在变更日志中区分上游同步内容和本项目差异化功能。

**预计材料**

- `README.md`
- `README_zh.md`
- `CHANGELOG.md`（如仓库已有则沿用）
- `plan/version-roadmap.md` 和各版本交接文档

### V100-04 分支和版本发布

**实现内容**

- 建立 `v1.0.0-rc` 验收点。
- 经明确授权后把产品主分支切换为 `main`。
- 保留上游分支/远程跟踪关系，后续同步不覆盖产品主线。
- 创建 `v1.0.0` 标签和发布说明。
- 发布前保存最终数据库备份并完成安装/升级冒烟测试。

**边界**

- 不强制合并 companion。
- 不因 WebSocket、供应商分组或排序功能未完成而阻塞发布。
- 远程推送、Release、PR 和权限设置必须另行授权。

## v1.0.0 完成条件

- 核心网关能力、渠道管理和监控链路可以独立运行。
- 上游阶段计划与本项目版本计划有清晰边界。
- 文档、迁移、备份和回归结果足以支持用户升级和回滚。
