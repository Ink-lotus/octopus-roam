# R1 首个独立版本收口

> 里程碑 `R1`，对外发布 `v0.1.0-rc.1` → `v0.1.0`。文件名沿用旧编号，仅作文档标识，不代表对外版本号。

## 版本目标

把 `M1`～`M3` 的功能收口为可独立发布的产品版本，完成兼容检查、文档、主分支和发布标签。首个独立版本不等待生图、管理界面增强或 WebSocket。

## 进入条件

- `S1` 上游同步完成并建立新基线。
- `M1` 路由策略和隐私保护完成。
- `M2` 手动渠道刷新、分组同步、日志筛选和协议/禁用渠道管理完成。
- `M3` 自动同步和渠道并发限制完成。
- 工作区无未说明改动，现有 Go 和前端检查通过。

## 实现顺序

### V100-01 数据迁移与备份兼容审计

**实现内容**

- 列出所有新增设置、渠道字段、分组字段和匹配模式字段。
- 为旧数据库提供默认值，默认行为保持兼容。
- 确认旧备份版本可以导入，新备份包含新配置。
- 验证空模型渠道、空分组、失效分组成员和隐藏渠道不会破坏导入。
- 不删除已有旧迁移记录；新增迁移保持单调递增。
- 备份增加产品身份和独立内容版本 `1000`，下载采用口令加密容器；见[加密设计](../../docs/backup-encryption-design.md)与[迁移审计](../r1-migration-audit.md)。

**预计材料**

- `internal/db/migrate/`
- `internal/model/backup.go`
- `internal/op/backup.go`
- `internal/model/setting.go`
- 渠道、分组模型和测试夹具

**验收**

- 上游无标识 `0`/`5` 备份及本产品 `1000` 内容可导入；无标识 `6`（阶段 4/5 预发布格式）明确拒绝，并提示从原数据库重新导出。
- 新版本导出的备份可以再次导入。
- 下载文件加密全部备份内容，不包含敏感字段明文；错误口令/篡改失败时不写数据库。

**验证**

- `go test ./internal/db/... ./internal/op ./internal/server/handlers -count=1`
- 旧备份导入、新备份导出和重复导入测试。

### V100-02 全量回归和构建

**验证内容**

- Relay 手动模式和故障转移模式。
- 路由默认值仅更新策略参数，不改变分组模式。
- 渠道模型刷新成功、空结果、Key 失败和事务回滚。
- 严格匹配和关键词匹配。
- 分组成员删除、追加和当前成员清理。
- 协议限制、禁用渠道隐藏和前端保存。
- 日志请求中置顶、筛选、取消和 SSE 重连。
- 全局自动更新、渠道退出、刷新锁和并发限制。
- Webhook 失败/恢复通知和脱敏。

**验证命令**

- `go test ./... -count=1`
- `go test -race ./internal/relay ./internal/server/handlers -count=1`
- `go vet ./...`
- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v100-build" --emptyOutDir false`
- `git diff --check`

### V100-03 文档与运行配置收口

**实现内容**

- 更新 README、中文 README、配置示例和升级说明。
- 记录新设置的默认值、空模型渠道行为、自动更新风险和回滚方式。
- 记录分组匹配模式、路由默认策略覆盖规则和日志状态定义。
- 停用固定指向上游的自更新，独立版本采用手动升级；发布仓库和升级校验确定后再设计启用。
- 增加故障排查章节：Key 失败、模型为空、并发排队、Webhook 失败。
- 在变更日志中区分上游同步内容和本项目差异化功能。

**预计材料**

- `README.md`
- `README_zh.md`
- `CHANGELOG.md`（如仓库已有则沿用）
- `plan/version-roadmap.md` 和各版本交接文档

### V100-04 分支和版本发布

**实现内容**

- 经明确授权后创建 `main` 分支，确认已修的 `release.yaml` 在其上生效，再切换默认分支。
- 保留上游分支和远程跟踪关系；`master` 作为上游同步分支，不再触发发布。
- 在 `main` 上修改 `main.go` 发 `v0.1.0-rc.1`，建立 rc 验收点。
- rc 验收通过后创建 `v0.1.0` 标签和发布说明。
- 发布前保存最终数据库备份并完成安装/升级冒烟测试。

**边界**

- 不强制合并 companion。
- 不因 WebSocket、供应商分组或排序功能未完成而阻塞发布。
- 远程推送、Release、PR 和权限设置必须另行授权。

## R1 完成条件

当前执行结果见 [r1-result.md](../r1-result.md)。工作区实现与本地验收不代表分支/版本发布已完成；MySQL/PostgreSQL 实例验收与远程发布仍需完成。

- 核心网关能力、渠道管理和监控链路可以独立运行。
- 上游阶段计划与本项目版本计划有清晰边界。
- 文档、迁移、备份和回归结果足以支持用户升级和回滚。
