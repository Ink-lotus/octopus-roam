# v0.1.0 路由策略基础版

## 版本目标

把手动模式和故障转移模式的配置语义整理清楚，建立可复用的全局默认策略，并在公开发布前完成确定性隐私保护。这个版本不改变分组模式，不批量把手动分组切换为故障转移分组。

M1 实现和规定的自动检查已于 2026-09-29 完成，详见 [M1 验收记录](../m1-route-policy-result.md)。浏览器人工交互验收未执行。

## 依赖和范围

- 基线是 `S1` 上游同步建立的新 commit，不是本文档编写时的 `test` 分支状态；开工前用 `git rev-parse HEAD` 复核。
- 阶段 2 的故障转移状态机、阶段 3 的运行时状态和阶段 4 的 Webhook 继续保留。
- 不实现渠道模型刷新、自动同步、生图和 WebSocket；这些功能分别进入 `v0.2.0` 及后续版本。
- 保持现有 `GroupRelayConfig` 扁平 JSON 和旧备份可读取，首版不做嵌套配置的大迁移。

### V010-02 确定性隐私保护（已完成）

**目标**

统一处理凭据和敏感请求信息，保证同一敏感值在同一展示范围内使用稳定的掩码或哈希，同时不把原始凭据带入日志、Webhook 和诊断响应。

**实现内容**

- API Key、Authorization、Webhook 密钥、URL 用户信息、敏感查询参数和自定义敏感 Header 统一脱敏。
- Relay 错误、请求日志、Webhook 事件使用同一套脱敏规则。
- 需要关联排查的字段使用稳定值；不可逆内容不回写数据库。
- 保留按需读取请求体/响应体的现有能力，但对其中的敏感字段明确边界。

**预计材料**

- `internal/relay/state.go`
- `internal/server/handlers/log.go`
- `internal/webhook/template.go`
- `internal/webhook/service.go`
- 相关测试和三份 locale（如界面文案需要调整）

**边界**

- 不改 Relay 重试和选路逻辑。
- 不重新引入 companion 状态接口。
- 不新增第三方依赖。

**验收**

- 日志、Webhook 和错误响应中不出现 API Key、Authorization、渠道凭据、URL 密码和敏感查询参数。
- 相同输入的稳定掩码结果一致，不同输入不会暴露原文。
- 非敏感错误信息仍可用于定位渠道和请求问题。

**验证**

- `go test ./internal/relay ./internal/server/handlers ./internal/webhook -count=1`
- `go vet ./...`
- 使用固定敏感样本做脱敏断言。

### V010-03 拆分路由策略的模式语义（已完成）

**目标**

让配置和界面明确区分公共参数、手动参数和故障转移参数。路由执行层已有模式分支，主要补齐配置层和界面层。

**字段语义**

| 类别 | 字段 | 生效模式 |
| --- | --- | --- |
| 公共 | `member_non_stream_response_timeout_seconds` | 两种模式 |
| 公共 | `member_stream_first_event_timeout_seconds` | 两种模式 |
| 公共 | `retry_mode`、固定/指数间隔 | 两种模式 |
| 手动 | `manual_max_attempts` | 手动 |
| 故障转移 | `member_max_attempts` | 故障转移 |
| 故障转移 | `member_cooldown_seconds` | 故障转移 |
| 兼容 | `member_affinity_seconds` | 不再参与路由，旧数据可读取 |

**实现内容**

- 后端按当前 `Group.Mode` 校验和归一化字段。
- 手动模式不显示冷却、故障转移尝试上限和亲和时间。
- 故障转移模式不显示手动尝试上限。
- `member_affinity_seconds` 不再写入新的有效策略，运行时保持兼容字段为零。
- 切换单个分组模式时重置该分组运行时路由状态，清理冷却和探测残留。

**预计材料**

- `internal/model/group.go`
- `internal/op/group.go`
- `internal/relay/handler.go`
- `internal/relay/route.go`
- `internal/server/handlers/group.go`
- `web/src/api/group.ts`
- `web/src/components/modules/group/Editor.tsx`
- `web/src/components/modules/group/MemberStatus.tsx`
- `web/src/locales/{zh_hans,zh_hant,en}.json`

**边界**

- 不修改 `Group.Mode` 的持久化值和 API 枚举。
- 不批量修改已有分组模式。
- 不改变成员优先级和手动选择成员。

**验收**

- 手动模式不会因为冷却或故障转移字段触发切换。
- 故障转移模式仍按尝试上限和冷却时间工作。
- 旧分组和旧备份可以读取并正常运行。
- 前端不再给手动模式展示无效的冷却/亲和设置。

**验证**

- `pnpm lint`

### V010-04 全局默认路由策略（已完成）

**目标**

为新建分组提供统一的 Relay 默认参数，并允许管理员一次性把策略参数应用到已有分组。全局设置不包含、也不修改分组模式。

**建议数据形状**

概念上分为公共、手动和故障转移三部分；存储首版可以继续使用现有 `Setting` 表的 JSON 字符串，以避免新的数据表迁移。

```json
{
  "common": {},
  "manual": {"manual_max_attempts": 0},
  "failover": {"member_max_attempts": 2, "member_cooldown_seconds": 60}
}
```

实际接口可以继续返回现有扁平 `GroupRelayConfig`，由后端按模式决定生效字段。

**实现内容**

- 增加类型明确的读取和保存接口，例如：
  - `GET /api/v1/group/route-defaults`
  - `POST /api/v1/group/route-defaults`
- 新建分组时读取全局默认策略；用户选择的分组模式仍由创建请求决定，未选择时继续默认手动。
- 保存时提供“同时应用到已有分组”选项。
- 不覆盖时只更新默认值。
- 覆盖时在一个事务中：
  - 公共参数更新所有分组；
  - 手动参数更新手动分组；
  - 故障转移参数更新故障转移分组；
  - 保留分组模式、名称、成员、顺序和 `active_item_id`；
  - 重置受影响分组的运行时路由状态；
  - 刷新缓存并发布分组变更事件。
- 使用现有设置备份机制导出和导入全局默认值。

**预计材料**

- `internal/model/setting.go`
- `internal/op/setting.go`
- `internal/op/group.go`
- `internal/server/handlers/group.go`
- 新增或扩展 `internal/server/handlers/setting.go`
- `web/src/api/group.ts`、`web/src/api/setting.ts`
- `web/src/components/modules/group/Editor.tsx`
- `web/src/components/modules/setting/`

**边界**

- 不提供批量修改 `Group.Mode` 的入口。
- 不批量重排成员，不修改分组成员集合。
- 批量应用失败时整批回滚。

**验收**

- 修改默认值后，新建分组获得新参数。
- 不勾选覆盖时，已有分组 JSON 完全不变。
- 勾选覆盖时，已有分组只改变策略参数，模式和成员保持不变。
- 批量应用后冷却、探测和旧等待请求不会继续使用旧策略。

**验证**

- `go test ./internal/op ./internal/server/handlers ./internal/relay -count=1`
- `go vet ./...`
- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v010-defaults-build" --emptyOutDir false`
- 旧备份导入和新备份导出测试。
