# v1.1.0 生图接口

## 版本目标

补齐 OpenAI 兼容的生图调用入口，让客户端可以通过网关调用支持生图的上游渠道。首版控制范围，避免同时引入编辑、变体和 Multipart 的兼容复杂度。

## 范围

首版支持：

- `POST /v1/images/generations`；
- OpenAI 风格 JSON 请求和响应；
- 渠道、Key、模型和统计链路复用现有机制；
- 非流式生图结果。

首版暂缓：

- 图片编辑；
- 图片变体；
- Multipart 请求；
- 生图流式传输；
- 不同厂商的专用图片协议。

## 实现顺序

### V110-01 生图请求模型和路由

**实现内容**

- 参照现有 Chat/Responses/Anthropic 路由注册 OpenAI 图片生成入口。
- 校验 `model`、`prompt`、尺寸、数量和响应格式等基础字段。
- 复用 API Key 认证、分组查找、渠道选择和错误响应。
- 明确图片请求是否允许进入手动/故障转移分组。

**预计材料**

- `internal/server/handlers/`
- `internal/relay/`
- `internal/model/`
- 路由注册和协议转换文件
- `web/src/api/`（如管理端需要展示协议能力）

**边界**

- 不修改现有文本请求路由。
- 不引入新的外部 SDK；优先复用 `axonhub` 已有图片请求/响应类型。

**验收**

- 标准 OpenAI 生图请求可以命中正确渠道。
- 模型不存在、协议不允许、参数非法和上游错误都有明确响应。
- 文本请求回归不受影响。

### V110-02 上游图片 Transformer 和响应归一化

**实现内容**

- 使用已有图片请求/响应 Transformer 转换渠道请求。
- 将上游图片 URL、Base64 或其他受支持结果归一化为 OpenAI 响应。
- 处理上游错误、空结果和部分结果。
- 将请求状态、耗时、错误和用量接入现有日志和统计链路。

**预计材料**

- `internal/relay/`
- `internal/rhttp/`
- `internal/price/`（只有统计需要时才修改）
- `internal/model/` 和日志相关代码

**验收**

- URL 和 Base64 两类响应按支持范围正确返回。
- 生图请求的失败、取消和超时会进入日志终态。
- 凭据和上游地址继续脱敏。

### V110-03 生图测试和文档

**验证**

- 使用本地 `httptest` 上游覆盖成功、错误、空结果、超时和取消。
- `go test ./... -count=1`
- `go vet ./...`
- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v110-build" --emptyOutDir false`

**文档**

- 更新 README 中支持的图片接口、模型配置和已知限制。
- 给出客户端请求示例和渠道协议要求。

## v1.1.0 完成条件

- OpenAI `/images/generations` 可稳定调用。
- 生图请求和普通文本请求的日志、统计、错误处理一致。
- 编辑、变体、Multipart 和专用厂商协议明确列为后续范围。
