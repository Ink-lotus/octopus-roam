# v1.2.0 管理体验增强版

## 版本目标

改善渠道和分组数量增加后的查找、排序和分组体验。展示顺序与 Relay 路由优先级分开保存，任何界面排序都不改变请求选路。

## 范围

- 渠道自定义排序和管理分组。
- 分组按供应商分组。
- 分组自定义排序。
- 继续保留名称排序和启用/禁用筛选。

## 实现顺序

### V120-01 确定展示元数据和持久化方式

**实现内容**

- 确定渠道供应商字段来源：显式配置、渠道类型推导或二者结合。
- 增加渠道展示分组和展示顺序字段，默认值保持当前名称排序。
- 增加分组展示顺序字段；不要复用 `GroupItem.Priority`，后者是成员路由顺序。
- 明确展示分组是否只对当前管理员生效。首版建议持久化到服务端，保证多个管理端看到一致顺序。
- 为旧数据提供空值和名称排序回退。

**预计材料**

- `internal/model/channel.go`
- `internal/model/group.go`
- `internal/op/channel.go`、`internal/op/group.go`
- 数据迁移和备份文件
- `web/src/api/channel.ts`、`web/src/api/group.ts`

**边界**

- 不改变渠道路由优先级。
- 不改变分组成员优先级和故障转移顺序。
- 不在本任务实现供应商自动识别的复杂规则。

**验收**

- 旧数据没有展示字段时仍按名称正常显示。
- 修改展示顺序不会改变 `/v1` 请求命中的渠道和分组成员顺序。
- 导出、导入后展示元数据保持一致。

### V120-02 渠道排序和管理分组

**实现内容**

- 渠道页面增加自定义排序入口。
- 增加渠道管理分组创建、重命名、调整顺序和取消分组。
- 保留名称排序、启用/禁用筛选和模型搜索。
- 渠道刷新、启用/禁用和删除后保持展示分组关系的正确性。
- 分组列表支持折叠和快速定位。

**预计材料**

- `web/src/components/modules/channel/`
- `web/src/api/channel.ts`
- `web/src/locales/{zh_hans,zh_hant,en}.json`
- 对应后端管理 API 和模型文件

**边界**

- 不把禁用渠道自动删除出管理分组。
- 不把展示分组混入渠道模型自动刷新逻辑。

**验收**

- 管理员可以按自定义顺序查看渠道。
- 渠道数量较多时可以按管理分组快速定位。
- 刷新和启停渠道后顺序、分组仍稳定。

**验证**

- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v120-channel-build" --emptyOutDir false`
- 多渠道、空分组、删除分组和旧数据回退手动验收。

### V120-03 分组供应商分组和自定义排序

**实现内容**

- 分组列表增加供应商维度展示。
- 支持自定义分组顺序和供应商分组顺序。
- 未识别供应商进入“其他”或未分类区域。
- 保留按名称排序，排序切换只影响展示。
- 分组实时事件更新时维护当前排序和分组位置。

**预计材料**

- `web/src/components/modules/group/`
- `web/src/api/group.ts`
- `internal/model/group.go` 或供应商派生接口
- 三份 locale

**边界**

- 不改变 Relay 的 `Priority`。
- 不在界面排序时重写 `GroupItem.Priority`。

**验收**

- OpenAI、Anthropic、DeepSeek 等供应商可以按预期分组。
- 自定义顺序在刷新和重新登录后保持。
- 分组成员拖拽排序仍只影响路由优先级，不影响列表展示顺序。

### V120-04 管理界面回归

**验证**

- `go test ./... -count=1`
- `go vet ./...`
- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v120-build" --emptyOutDir false`
- 手动验证展示顺序与实际请求选路不发生关联。

## v1.2.0 完成条件

- 渠道和分组可以在大规模配置下快速定位。
- 展示排序、管理分组和路由顺序完全分离。
- 旧数据、备份和实时事件继续可用。
