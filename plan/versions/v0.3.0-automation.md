# v0.3.0 自动化稳定版

## 版本目标

在 `v0.2.0` 手动刷新稳定后，增加全局渠道自动更新、渠道级退出控制、自动分组添加和渠道并发限制，使版本具备长期运行能力。

## 依赖和范围

- 复用 `v0.2.0` 的公共刷新服务和分组同步服务，不再复制一套自动刷新逻辑。
- 不复用现有 `model_info_update_interval`，该设置继续用于模型价格/信息更新。
- 不实现 WebSocket、生图和自定义排序。

## 实现顺序

### V030-01 全局渠道自动更新设置

**目标**

提供全局自动更新开关、周期和渠道跟随策略。

**实现内容**

- 增加独立的渠道自动更新设置：总开关、更新周期、默认是否执行分组自动添加。
- 为渠道增加“跟随全局更新”配置。
- 全局任务只选择跟随全局的渠道。
- 首次上线全局开关默认关闭，避免升级后立即清理渠道旧模型。
- 手动刷新继续可以单独执行，不受全局开关影响。

**预计材料**

- `internal/model/setting.go`
- `internal/op/setting.go`
- `internal/model/channel.go`
- `internal/task/`
- `internal/server/handlers/setting.go`
- `internal/server/handlers/channel.go`
- `web/src/api/setting.ts`
- `web/src/api/channel.ts`
- `web/src/components/modules/setting/`
- `web/src/components/modules/channel/`

**边界**

- 不修改模型价格更新任务。
- 不改变渠道默认启用状态。
- 不为 companion 增加任何消费接口。

**验收**

- 全局关闭时没有自动刷新。
- 渠道关闭跟随后不会被自动更新。
- 手动刷新不受全局开关影响。
- 周期修改后任务无需重启即可生效。

**验证**

- `go test ./internal/task ./internal/op ./internal/server/handlers -count=1`
- 设置读写、默认值和任务注册测试。
- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v030-settings-build" --emptyOutDir false`

### V030-02 自动刷新任务和逐 Key 结果

**目标**

让自动刷新具备单任务锁、可观察结果和失败保护。

**实现内容**

- 调度器按渠道逐个执行 `RefreshChannelModels`。
- 同一渠道同时只有一个刷新任务；手动刷新遇到自动任务时返回正在执行或合并为一次任务。
- 保持“所有启用 Key 成功后提交、任一失败保留旧状态”的事务语义。
- 记录最近一次刷新时间、状态、逐 Key 成功/失败、模型数量变化和错误摘要。
- 增加合理的重试和退避，避免公益站暂时异常时高频请求。
- 自动刷新使用与手动刷新相同的 `auto_add_groups` 选项和分组匹配模式。

**预计材料**

- `internal/op/channel_refresh.go`
- `internal/task/`
- `internal/model/channel.go` 或独立刷新状态模型
- `internal/server/handlers/channel.go`
- `web/src/api/channel.ts`
- 渠道卡片和设置页

**边界**

- 不允许失败的 Key 结果覆盖成功历史。
- 不在刷新失败时清空旧模型。
- 不改变已有分组实体。

**验收**

- 自动任务和手动按钮不会重复执行同一渠道。
- 单 Key 失败时渠道和分组保持旧状态。
- 所有 Key 成功返回空列表时可以清空渠道模型和对应分组成员。
- 自动添加只追加已有分组中符合规则的模型。

**验证**

- `go test ./internal/op ./internal/task ./internal/server/handlers -count=1`
- 多 Key 并发、单 Key 失败、任务取消和重复触发测试。

### V030-03 渠道级并发限制

**目标**

限制单个渠道同时承载的上游请求数量，防止某个渠道被大量请求拖垮。

**实现内容**

- 为渠道增加 `max_concurrency` 或等价配置，`0` 表示不限。
- 在真正发起上游请求前占用额度；等待路由、等待重试不占用额度。
- 流式请求直到响应结束、失败或取消才释放额度。
- 等待中的请求支持客户端取消，并立即释放等待位置。
- 删除、禁用或修改渠道并发配置时唤醒等待者。
- 提供当前占用数和等待数的诊断信息，首版不做复杂监控页面。

**预计材料**

- `internal/model/channel.go`
- `internal/op/channel.go`
- `internal/relay/handler.go`
- `internal/relay/state.go` 或新增并发控制文件
- `web/src/components/modules/channel/`
- 数据迁移、备份和配置校验文件

**边界**

- 首版只做渠道级限制，不做 Key 级限制和全局总并发限制。
- 不用轮询实现等待。
- 不改变故障转移成员冷却语义。

**验收**

- 并发数不超过渠道配置上限。
- `0` 保持原有不限行为。
- 流式、非流式、失败和取消都能释放额度。
- 等待中的请求在客户端取消后不会继续占用额度。
- 渠道切换和故障转移不会泄漏信号量。

**验证**

- `go test ./internal/relay ./internal/server/handlers -count=1`
- 固定上游延迟下的并发、队列、取消和流式测试。
- `go test -race ./internal/relay ./internal/server/handlers -count=1`
- `go vet ./...`

### V030-04 自动化运行验收

**目标**

验证模型刷新、分组同步、自动任务和并发限制组合使用时不会互相破坏。

**验收场景**

- 自动刷新返回新模型并按严格匹配追加到已有分组。
- 自动刷新返回空列表，渠道可保存为零模型，分组实体仍存在。
- 刷新过程中任一 Key 失败，旧模型、旧分组成员和路由状态保持。
- 自动刷新期间手动请求可以继续运行；刷新不会占用渠道调用并发额度。
- 渠道并发限制触发时，日志和取消行为正常。
- 全局关闭、渠道退出和重新加入全局任务均无需重启。

**验证**

- `go test ./... -count=1`
- `go vet ./...`
- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v030-build" --emptyOutDir false`
- 使用本地可控上游进行端到端手动验收。
