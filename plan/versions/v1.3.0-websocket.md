# v1.3.0 WebSocket 适配版

## 版本目标

在有明确客户端需求后增加 WebSocket 接入能力。现有 HTTP 透传和 SSE 监控链路保持独立；上游不支持 WebSocket 时，网关通过适配器转换到内部 HTTP/SSE 能力。

## 进入条件

- 已有客户端协议、消息格式、认证方式和断线重连要求。
- `v1.0.0` 核心 HTTP 能力稳定。
- 经过评估确认 WebSocket 的收益超过客户端适配和连接生命周期维护成本。

## 实现顺序

### V130-01 定义 WebSocket 客户端契约

**实现内容**

- 明确连接建立、认证、请求帧、响应帧、错误帧和结束帧。
- 明确一个连接承载单请求还是多请求。
- 定义流式增量、取消、超时、服务端关闭和重连语义。
- 定义协议映射到 Chat、Responses、Anthropic 和未来图片接口的边界。

**产出**

- 独立协议文档和 JSON 示例。
- 客户端兼容性清单。

**边界**

- 不直接把上游厂商私有 WebSocket 协议暴露为网关公共协议。
- 不修改已有 HTTP API 的请求和响应格式。

### V130-02 独立 WebSocket 路由和适配器

**实现内容**

- 增加独立 WebSocket Upgrade 路由。
- 复用现有认证、API Key、分组查找、协议选择和错误脱敏。
- 客户端 WebSocket 请求转换为内部统一 Relay 请求。
- 上游支持 HTTP/SSE 时，由网关将流式结果转换为 WebSocket 帧。
- 上游真正支持 WebSocket 时再增加专用上游适配器，不改变默认 HTTP 路径。

**预计材料**

- `internal/server/`
- `internal/relay/`
- `internal/rhttp/`
- `internal/model/`
- 依赖清单（已有 `gorilla/websocket` 时优先复用，不重复引入）

**边界**

- 不让 WebSocket 路由改变 HTTP 协议透传。
- 不为监控场景替换 Webhook 和现有 SSE。

**验收**

- WebSocket 客户端可以完成一次普通请求和一次流式请求。
- 上游仅支持 HTTP/SSE 时，客户端仍收到正确的 WebSocket 增量帧。
- 认证失败、协议不支持、上游错误和网关关闭都有明确帧或关闭码。

### V130-03 连接生命周期和资源控制

**实现内容**

- WebSocket 断开时取消对应 Relay 请求。
- 复用渠道并发限制，连接等待不泄漏额度。
- 设置连接空闲、单请求和总生命周期限制。
- 处理写入背压、慢客户端和上游结束后的连接关闭。
- 限制单连接消息大小，避免无界内存增长。

**预计材料**

- WebSocket handler 和 adapter
- `internal/relay/handler.go`
- `internal/relay/state.go`
- 渠道并发控制文件

**验收**

- 客户端断开后上游请求能够取消。
- 慢客户端不会阻塞其他请求。
- 连接、请求和并发限制在成功、失败、取消、超时路径都释放。

### V130-04 WebSocket 兼容性测试

**验证**

- WebSocket 握手、认证、普通响应、流式响应和取消测试。
- 上游 HTTP/SSE 适配测试。
- 慢客户端、断线重连、超时、消息过大和并发限制测试。
- `go test ./... -count=1`
- `go test -race ./internal/relay ./internal/server -count=1`
- `go vet ./...`
- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v130-build" --emptyOutDir false`

## v1.3.0 完成条件

- WebSocket 是独立适配层，现有 HTTP 透传行为没有回归。
- 上游不支持 WebSocket 时客户端仍可使用统一 WebSocket 接入。
- 连接断开、取消、背压和并发资源都能正确收敛。
