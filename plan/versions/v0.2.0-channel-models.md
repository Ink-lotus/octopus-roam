# v0.2.0 渠道模型管理版

## 版本目标

让渠道模型更新可手动触发、结果可控，并把刷新结果正确同步到已有分组成员。这个版本同时改善日志可见性、协议选择和禁用渠道的管理体验。

## 依赖和范围

- 依赖 `v0.1.0` 的路由策略和默认值契约。
- 阶段 6 companion 不重新引入；日志改动使用现有请求日志 SSE。
- 本版本只实现手动刷新。全局自动刷新和调度器进入 `v0.3.0`。
- 分组实体不创建、不删除、不重建；渠道刷新可以删除失效分组成员，也可以追加匹配的新成员。

## 实现顺序

### V020-01 日志请求中置顶和状态筛选

**目标**

避免长时间等待的请求被其他模型的成功日志推到不可见位置，并让用户快速查看当前仍在运行的请求。

**实现内容**

- 把 `running` 和 `committed` 视为请求中状态：
  - `running` 包括等待渠道、等待重试和等待上游响应；
  - `committed` 表示已经开始向客户端输出，但流式响应尚未结束。
- 日志列表默认按“请求中优先、同类按 Request ID 倒序”排序。
- `success`、`failed`、`canceled` 进入历史区域，仍按 Request ID 倒序。
- 增加本地状态筛选：全部、请求中、成功、失败、已取消。
- 筛选和排序在前端完成，不新增后端查询接口，不改变 SSE 数据格式。

**预计材料**

- `web/src/api/log.ts`
- `web/src/components/modules/log/index.tsx`
- `web/src/components/modules/log/Item.tsx`（如需状态提示）
- `web/src/locales/{zh_hans,zh_hant,en}.json`

**边界**

- 不增加数据库日志表。
- 不把已取消请求继续放在“请求中”区域。
- 不在首版增加模型、渠道、API Key 多条件查询。

**验收**

- 一个长时间 `running` 请求存在时，其他模型成功不会把它移到历史日志下面。
- 流式 `committed` 请求持续置顶，直到成功、失败或取消。
- 点击“请求中”只显示 `running` 和 `committed`。
- SSE 重连后顺序和筛选结果一致。

**验证**

- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v020-log-build" --emptyOutDir false`
- 手动验证长请求、流式请求、重试等待和取消请求。

### V020-02 公共渠道模型刷新服务

**目标**

将现有只读探测能力扩展为可持久化的渠道刷新流程，供渠道按钮和后续自动更新共用。

**实现内容**

- 新增公共刷新服务，例如 `RefreshChannelModels(ctx, channelID, options)`。
- 按启用 Key 逐个请求上游模型。
- 结果在内存中合并，所有启用 Key 都成功后一次事务提交。
- 上游成功返回空列表、全局过滤后为空列表时，允许渠道保存为零模型。
- 任一 Key 请求失败时保留旧模型、旧授权和旧分组成员，返回逐 Key 错误。
- 成功刷新时以本次结果替换渠道模型和授权；未返回授权被删除，依赖外键的对应分组成员随之清理。
- 返回新增模型、删除模型、零模型和 Key 失败信息，方便前端展示。
- 现有 `POST /api/v1/channel/fetch-model` 继续作为未保存探测接口，避免破坏渠道编辑器。

**预计材料**

- `internal/op/channel.go`
- 新增 `internal/op/channel_refresh.go` 或等价服务文件
- `internal/model/channel.go`、`internal/model/channel_grant.go`
- `internal/server/handlers/channel.go`
- `web/src/api/channel.ts`
- 渠道迁移和备份相关文件（只有新增字段时才修改）

**边界**

- 不使用软删除保留失效模型。
- 不在一次失败刷新中提交部分 Key 的结果。
- 不创建或删除 `Group` 行。

**验收**

- 成功刷新后旧模型不可再被选择。
- 成功空列表可以保存，渠道和分组中都没有该渠道的可用旧模型。
- 任一 Key 失败时旧状态完全保留。
- 刷新事务中途失败不会留下半套模型/授权。

**验证**

- `go test ./internal/op ./internal/server/handlers -count=1`
- 使用本地 `httptest` 上游覆盖多 Key 成功、空列表、过滤为空和单 Key 失败。
- `go vet ./...`

### V020-03 渠道卡片“更新模型”按钮

**目标**

把渠道模型刷新变成一个可直接执行的管理操作，减少进入编辑表单、逐 Key 探测和手动保存的步骤。

**实现内容**

- 渠道卡片增加“更新模型”按钮和进行中状态。
- 调用持久化刷新接口，不复用只读探测接口的临时表单合并逻辑。
- 展示每个 Key 的结果和总体结果：成功、空结果、失败、模型数量变化。
- 刷新完成后更新渠道列表、模型选择器和分组成员缓存。
- 提供一次性“刷新后按分组规则自动添加模型”选项；默认值沿用产品设置，不能隐式创建分组。

**预计材料**

- `web/src/components/modules/channel/`
- `web/src/api/channel.ts`
- `web/src/locales/{zh_hans,zh_hant,en}.json`
- `internal/server/handlers/channel.go`（接口注册或响应结构）

**边界**

- 不在本任务实现全局自动更新。
- 不在刷新按钮中修改分组模式、分组名称和成员顺序。

**验收**

- 一个按钮可以完成渠道模型刷新。
- 刷新期间不能重复提交同一渠道任务。
- 用户能看到逐 Key 失败原因。
- 刷新成功后页面无需手动刷新即可看到新模型和分组结果。

**验证**

- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v020-channel-button-build" --emptyOutDir false`
- 手动覆盖成功、失败、空结果和重复点击。

### V020-04 分组模型匹配模式

**目标**

解决关键词包含匹配导致模型变体误加入分组的问题，同时保持已有分组的旧行为。

**实现内容**

- 为分组增加模型自动添加匹配模式，建议值为 `keyword` 和 `exact`。
- 已有分组默认 `keyword`，确保升级不改变现有行为。
- `keyword` 保持当前大小写不敏感的包含匹配。
- `exact` 对去除首尾空格后的完整模型名称做大小写不敏感相等匹配。
- 把匹配函数从 `web/src/components/modules/group/Editor.tsx` 提取为前后端可复用的明确规则；刷新服务、编辑器预览和手动自动添加使用同一规则。
- 首版不支持正则、通配符和前缀匹配。

**预计材料**

- `internal/model/group.go`
- `internal/op/group.go`
- 新增匹配工具文件（位置按现有包结构决定）
- `internal/server/handlers/group.go`
- `web/src/api/group.ts`
- `web/src/components/modules/group/Editor.tsx`
- 三份 locale

**边界**

- 不自动修改已有分组成员。
- 不改变分组成员优先级。
- 不删除用户手动加入但不匹配名称的成员；删除由渠道刷新失效同步负责。

**验收**

- `claude-opus-5` + `keyword` 会匹配 `claude-opus-5-5`。
- `claude-opus-5` + `exact` 只匹配 `claude-opus-5`。
- 编辑器预览和渠道刷新得到相同结果。

**验证**

- 后端匹配单元测试。
- `pnpm lint`
- `pnpm build --outDir "$env:TEMP/octopus-v020-match-build" --emptyOutDir false`

### V020-05 刷新后的分组成员同步

**目标**

把渠道刷新结果同步到已有分组成员，同时保持分组实体和用户配置稳定。

**实现内容**

- 刷新成功后删除该渠道已经失效的 `GroupItem` 引用。
- 删除当前手动选中成员时清空无效的 `active_item_id`，沿用现有清理逻辑。
- 仅在刷新选项 `auto_add_groups=true` 时追加新获取且匹配分组名称的模型。
- 追加成员放在分组末尾，保留现有成员顺序、优先级和其他渠道成员。
- 只处理已存在的分组，不创建、不删除、不重命名分组。
- 渠道刷新和成员同步尽量放在同一数据库事务中；失败时整体回滚。
- 刷新后发布分组变更事件并刷新缓存。

**预计材料**

- `internal/op/channel_refresh.go`
- `internal/op/group.go`
- `internal/server/handlers/channel.go`
- `internal/server/handlers/group.go`
- `internal/relay/route.go`（只在状态重置需要时修改）

**边界**

- 不恢复以前删除的成员位置；模型再次出现时按匹配模式重新加入并放在末尾。
- 不修改分组模式和路由策略。

**验收**

- 模型从上游消失后，对应渠道成员从分组中消失。
- 新模型匹配时追加到已有分组。
- 关闭自动添加时不新增成员，但仍清理失效成员。
- 上游返回空列表时可以留下空分组，不删除分组实体。
- 同名模型来自其他渠道时不会被误删。

**验证**

- `go test ./internal/op ./internal/relay ./internal/server/handlers -count=1`
- 覆盖事务失败、当前成员被删、自动添加关闭和多渠道同名模型。

### V020-06 渠道协议启用/禁用

**目标**

让渠道只参与用户明确允许的协议，避免刷新模型时为不支持的协议建立授权。

**实现内容**

- 为渠道增加协议允许位掩码，默认值保持当前支持的三种协议。
- 有效协议 = 渠道允许协议与 `ChannelGrant.Protocols` 的交集。
- 刷新模型、创建授权、分组候选和 Relay 选路统一使用有效协议。
- 首版做渠道级开关；Key 级协议开关作为后续扩展，不在本任务增加。
- 修改协议设置后清理对应无效授权，并同步分组成员。

**预计材料**

- `internal/model/channel.go`
- `internal/model/channel_grant.go`
- `internal/op/channel.go`、`internal/op/channel_refresh.go`
- `internal/relay/`
- `web/src/components/modules/channel/`
- `web/src/api/channel.ts`
- 数据迁移和备份文件（新增字段需要默认全部启用）

**边界**

- 不清除上游原始能力记录之外的无关渠道配置。
- 不改变现有入站协议转换行为。

**验收**

- 禁用某协议后，该渠道不会为该协议出现在新授权和分组候选中。
- 旧渠道升级后默认行为不变。
- 修改协议后路由运行状态被正确刷新。

**验证**

- `go test ./internal/op ./internal/relay ./internal/server/handlers -count=1`
- 三种协议的授权、刷新和路由测试。
- `pnpm lint`、`pnpm build --outDir "$env:TEMP/octopus-v020-protocol-build" --emptyOutDir false`

### V020-07 禁用渠道在分组界面隐藏

**目标**

让手动选择分组成员时不被禁用渠道干扰，同时保留已有引用以便恢复或清理。

- 已存在的失效成员不能因为前端隐藏而在提交时被自动删除。
- 已有成员可显示不可用状态或进入单独清理入口，具体展示沿用当前分组编辑器结构。
- 渠道重新启用后候选重新出现。

**预计材料**

- `web/src/components/modules/group/ItemList.tsx`

**验收**

- 禁用渠道不出现在新选择候选中。
- 已有分组成员不会因打开并保存编辑器而被误删。
- 启用渠道后无需重建分组即可恢复候选。

**验证**

- `pnpm lint`
- 手动验证隐藏、保存、重新启用和已有成员清理。

## v0.2.0 完成条件

- 日志能稳定查看所有长时间请求，并可筛选请求中状态。
- 手动刷新能原子更新渠道模型和授权，支持空结果。
- 分组成员按刷新结果删除失效成员，并按匹配模式追加新模型。
- 协议限制和禁用渠道不会产生新的无效候选。
- `v0.1.0` 的路由策略和默认值行为没有回归。
