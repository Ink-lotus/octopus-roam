# 云数据库自动验收：凭据与会话交接

日期：2026-10-10。关联计划：[v0.1.0 发布计划](release-plan-v0.1.0.md)。

分工已经明确：用户准备 MySQL、PostgreSQL 一次性云测试数据库；执行会话负责数据库自动验收，用户只负责 Docker 人工验收。2026-10-15 用户已提供仓库外 profile 位置并明确授权两个固定别名及范围，已实际执行：MySQL 迁移前 TLS 失败，PostgreSQL 空库检查通过后 migration 5 失败。执行范围、只读定位、留存表/记录及后续门禁见[环境验收报告](release-environment-acceptance-20261015.md)；两库均未通过，不直接重跑或清理。

## 1. 推荐的交接方式

两个云数据库只用于本次测试。用户在自己的独立终端创建仓库外的本地连接档案，测试完成后由用户负责重置远程数据库、处理测试账号并删除本地明文档案；执行会话不自动删库、删表、改密或清理云资源。真实连接信息不得进入 Git、工具输出、报告或会话文本。

采用类似 SSH Host 别名的本地连接档案。`db-profiles.json` 在本次测试中保存完整连接字段，包括主机、数据库、账号、密码和 TLS 参数；它只存在于用户的个人目录，不作为代码、构建或交付材料。建议档案位置为：

```text
~/.config/octopus-roam/db-profiles.json
```

这里的 `~` 指执行用户的个人目录，Windows 上对应 `%USERPROFILE%\.config\octopus-roam\db-profiles.json`。档案支持显式路径覆盖。用户自行创建并保管该文件，执行会话只接收必要的别名或文件路径，不接收文件内容。

本次采用一次性明文档案，不要求用户安装数据库客户端或第三方凭据库。测试入口在进程内读取字段并构造连接参数，不把密码拼进命令参数或环境变量；测试完成后由用户删除档案并按自己的安排重置远程数据库和测试账号。该文件在存在期间仍是明文凭据，不能复制到仓库、构建目录、日志、报告或交付包。

### 1.1 明文档案与会话边界

正常执行路径为：用户在独立终端准备档案 → 会话提交别名或档案路径 → 测试进程在内存中读取字段并连接数据库 → 只返回允许公开的测试字段。入口的验收要求是：密码、完整连接串、主机、账号和库名不得进入工具输出、报告或会话文本。后文要求限制标准输出、标准错误和异常信息，不能只过滤日志中的 `password` 字段。

明文档案只适合这次短期测试。能够读取该文件或以同一用户运行任意代码的进程都可能取得密码；测试后删除文件和重置远程账号可以缩短暴露窗口，但不能抹掉已经产生的 Shell 历史、进程转储、备份或云端审计记录。因此测试入口必须控制输出，用户仍应在独立终端创建文件。

如果之后要求“即使执行会话尝试读取，也拿不到凭据”，应另行配置独立 Windows 用户或受保护测试服务；这不属于本次一次性明文档案范围。

## 2. 别名文件模板与一次性测试配置

`db-profiles.json` 按下面的结构填写即可。顶层键是稳定别名，`type` 指定数据库引擎；其余字段是本次测试的连接参数。仓库内 `db-check` 入口读取该结构；应用正常启动仍只读取 `start --config`。

```json
{
  "roam-mysql-test": {
    "type": "mysql",
    "host": "<MySQL 主机名>",
    "port": 3306,
    "database": "<专用测试库名>",
    "restore_database": "",
    "user": "<测试账号>",
    "password": "<测试密码>",
    "tls": true,
    "ca_file": ""
  },
  "roam-postgres-test": {
    "type": "postgres",
    "host": "<PostgreSQL 主机名>",
    "port": 5432,
    "database": "<专用测试库名>",
    "restore_database": "",
    "user": "<测试账号>",
    "password": "<测试密码>",
    "sslmode": "verify-full",
    "channel_binding": "require",
    "ca_file": ""
  }
}
```

用户在自己的独立终端填写本次测试所需字段；交付模板和报告只保留上面的占位符：

| 字段 | 填写内容 |
| --- | --- |
| `type` | `mysql` 或 `postgres`，入口按类型选择驱动 |
| `host`、`port` | 云服务提供的地址和端口；3306、5432 只作为各自默认值 |
| `database` | 本次测试的专用数据库名 |
| `restore_database` | 同一实例上的专用恢复库名；尚未准备时留空 |
| `user`、`password` | 仅供本次测试的账号及密码；用户自行填写，不通过会话传递 |
| MySQL `tls` | 启用 TLS；需要额外 CA 时配合 `ca_file` |
| PostgreSQL `sslmode` | 按云服务要求填写，优先使用 `verify-full`；不得使用关闭 TLS 的配置 |
| PostgreSQL `channel_binding` | 云服务要求时填写 `require`，不能在转换 DSN 时丢弃 |
| `ca_file` | 云服务需要额外 CA 时填写本机证书路径；否则留空并使用系统信任根 |

使用说明：

- 别名只用于选择配置，不授予额外权限；入口拒绝路径分隔符、路径跳转、缺失字段和残留占位符。引擎以 `type` 为准，不从名字猜测。
- 主机、库名、账号、密码由程序分字段构造 DSN，避免手工处理密码中的 URI/DSN 转义。使用恢复库时，账号权限应包含明确指定的恢复库。
- MySQL TLS 和 PostgreSQL SSL 连接按云服务要求校验。证书验证失败先检查 CA、主机名和实际配置，不直接通过跳过校验解决。
- 如果只有云厂商提供的完整连接串，用户在独立终端把它拆分到上述字段；入口应在内存中处理 URI，不把完整连接串作为命令参数或输出。尤其不能把 `postgresql://...` URI 直接当作 Go MySQL DSN。
- 用户准备测试库和测试账号即可，账号需要测试库内建表、改表、索引及正常读写权限，不需要交付云平台管理员凭据。本次测试结束后的远程重置由用户负责，不由测试程序自动执行。
- 如果云数据库有 IP 白名单，用户开放本次执行机器所需的访问范围；此设置由用户完成，交接凭据不授权代理修改云网络设置。

### 2.1 别名如何被使用

连接过程约定为：用户/会话选择别名 → 启动器在进程内读取对应的明文 profile → 在内存中构造驱动参数 → 连接指定测试库。若启动器与 Go 验收程序分为两个进程，可通过继承的匿名管道传入，不经命令参数或临时文件中转；该管道同样不构成同一用户内的强制隔离。

当前项目的 `start --config` 只读取应用配置，其中数据库仍使用 `database.type` 与 `database.path`。独立的 `db-check` 命令按别名读取本文 profile，不把验收配置扩展成新的产品设置，也不需要为它新增数据库服务或 mysql/psql 客户端。

验收入口的接口要求：

- 接收显式的 profile/别名参数，默认不连接任何目标；默认文件是执行用户个人目录下的 `%USERPROFILE%\.config\octopus-roam\db-profiles.json`（Unix 为 `~/.config/octopus-roam/db-profiles.json`），也支持 `--profile` 覆盖。当前实现按 `os.UserHomeDir()` 拼接该路径，不使用 Windows `os.UserConfigDir()` 的 `%AppData%` 路径。离线检查命令为：`go run . db-check --profile <仓库外路径> --alias roam-mysql-test`。它只返回 `profile_valid` 或脱敏错误分类。
- 按别名精确查找配置，拒绝不存在的别名、重复条目、缺失类型、非法引擎、缺失连接字段或残留占位符。记录不匹配时停止，禁止回退到环境中的其他数据库或应用默认数据库。
- 提供仅检查档案结构和字段的离线检查，不建立连接、不回显密码；结果只返回字段是否有效。实际联网和写入仍按已审查的命令范围授权。
- 连接冒烟命令为：`go run . db-check --profile <仓库外路径> --alias roam-mysql-test --connect`。`--connect` 才会建立指定数据库连接、执行当前版本迁移、初始化默认设置并执行一次 `SELECT 1` 与无数据变化的设置写入；它不自动清库、删表、切换到 `restore_database` 或执行完整恢复套件。执行前仍需针对所选别名取得数据库连接和写入授权。
- 正常测试使用两个已声明别名分别运行，报告绑定实际别名、测试批次和数据库类型。文件路径只是定位材料，别名也不授予额外权限；连接目标变更后重新核实授权范围。
- 下一会话交付档案结构检查、按别名运行入口与结果格式；先用虚构 profile 验证正常输出、连接失败、解析失败、TLS 失败和异常处理不会泄露输入，再由用户在自己的终端填写真实连接信息。设置私有目录、写入凭据或更改文件权限仍需用户执行或获得对应授权。
- 仍遵守第 4 节的明文档案和日志规则；不能因为档案位于用户目录就放宽输出控制。

`~/.ssh/config` 本身只供 SSH 使用，当前数据库驱动不会把其中的 Host 别名当作数据库连接档案。若数据库必须经 VPS 访问，可以另用已配置的 SSH Host 建立隧道，再让数据库档案使用本机转发端口；SSH 登录和数据库认证仍各自配置。是否使用隧道由实际网络条件决定，不能为了支持别名就自动增加 VPS 或建立远端隧道。

## 3. 一次性测试数据与恢复验收

MySQL 和 PostgreSQL 的实例、专用测试账号、密码及连接别名只用于本次测试。测试前使用专用测试库和合成数据；测试结果记录本次执行的空库用例和恢复用例，不把已有内容的库启动写成空库初始化通过。测试结束后由用户删除本地明文档案、重置远程数据库并处理测试账号；执行会话不自动删库、删表或改密。

测试程序记录自己创建的数据，在本次已明确授权的范围内自动清理对应合成数据；全局设置的测试需要保存并恢复原值，同一测试库的写入验收应串行运行。不能假定所有写入都能靠一个外层事务回滚，实际重启、刷新及导入仍需真实提交。失败后留下的数据应在脱敏结果中注明待处理范围，不能为了方便重试扩大清理。

空库初始化和完整空库恢复需要单独的空目标。优先在同一服务实例下准备专用恢复逻辑库，填入 `restore_database`，通常不需要另购实例。若只有一个逻辑库，先完成不依赖空目标的用例；需要重置专用测试表时，先说明被清理的内容和数据保留方法，获得对应授权后再执行，最终由用户按本次测试安排重置远程数据库。不能把已有库的增量导入写成空库恢复。

默认不清空测试库、不删除库或表，也不因为名字含有 test 就认定其中数据可以删除。入口先核对空目标条件；目标已有内容时报告该用例待验，继续独立的可执行步骤。对已有库增量导入不能替代空库恢复。数据库连接凭据的生命周期与测试数据清理相互独立。

已有单元测试主要使用临时 SQLite。不能只改环境变量就认定这些测试已覆盖云端 MySQL/PostgreSQL。下一会话要准备单独的集成测试入口，使用现有驱动、初始化和业务函数或 API，针对实际目标执行发布计划 L5.3 的流程。

## 4. 执行会话的凭据处理规则

1. 只接收别名和必要的文件路径；先完成本地测试程序、命令与影响说明，按用户授权门禁确认云数据库读写范围。获得授权后，只连接所选别名对应的测试目标。
2. 由本地启动器/测试进程在内存中读取明文记录并生成连接配置。工具调用中只传别名和必要的档案路径；不把 DSN、密码或读取值拼进命令行、会话可见的环境变量或临时脚本，不打印 profile 内容。
3. 不使用 `Get-Content`、打印环境变量、调试日志或异常转储把私有内容输出给会话。收集并控制所有子进程的 stdout/stderr，不把未经检查的输出直接转发。仅输出预先允许的字段，例如别名、引擎、用例、通过/失败、错误分类、耗时及脱敏证据位置；字段值不能夹带原始错误文本。
4. 连接失败时输出 `authentication_failed`、`tls_validation_failed`、`connection_timeout` 等错误分类；未知异常返回统一的 `test_failed`。数据库驱动错误可能包含主机、账号或连接参数，不能原样输出。需要详细诊断时由用户在本地查看，不把原始错误、转义后的连接串或调试转储带入会话。
5. 真实别名档案、生成的含凭据配置、原始日志和云证书材料都不能进入 Git、Docker 构建上下文、镜像层、验收交付包或发布附件。构建包按文件清单生成，不打包整个父目录；文档示例只含合成值。
6. 只使用合成渠道 Key、测试模型接口、测试 Webhook 和测试数据。云数据库访问授权不涵盖真实供应商调用、GitHub 更新、价格同步或其他外网请求。
7. 专门的数据库测试入口应避开无关启动任务；如果启动完整程序，先处理启动即执行的联网价格更新和版本检查。必要时只对已授权的数据库目标开放连接。
8. 每种数据库分别记录软件版本、已执行用例、结果与证据文件位置，目标使用实际选择的 `roam-mysql-test`、`roam-postgres-test` 等别名；报告不包含私有连接参数。
9. 测试程序不得把收到的云平台控制台链接、管理员凭据或其他库当作可操作目标。清库、删表、创建其他数据库和调整云服务设置不属于默认授权。
10. 测试结束只关闭连接并处理已授权的本次合成数据；测试程序不自动删除档案、删库、删表或改密。测试完成后由用户删除明文档案、重置远程数据库并处理测试账号；测试程序启动时不得自动覆盖 profile，连接信息更新作为用户独立终端中的显式编辑处理。

## 5. 授权与第一轮边界

使用这两个云测试库可以作为“第一轮只做本地”的一项单独授权例外。例外范围限定为已确认测试目标的数据库集成验收；GitHub、registry、分支/标签、Release、镜像发布及其他远端操作继续暂缓。

用户的 AGENTS.md 将数据库变更列为必须先说明目标、命令、影响并获得明确授权的操作。因此凭据文件只提供连接材料；执行会话仍需先把测试入口、实际命令、初始化/读写影响和恢复方法准备好，再取得对应授权。授权明确后不重复询问同一范围；不能用“已收到凭据”推导出清库或任意远端操作许可。

建议授权分为两个具体范围：

- 正常验收：指定测试库内的应用初始化、合成数据的增删改查、模型同步、事务检查、备份导出及指定空恢复库的导入；为重复测试自动清理本批次合成行、恢复设置可包含在这次明确授权中。
- 空目标准备：需要重置测试表时先列出准确目标、命令与影响，作为单独范围或本次测试方案的明确步骤授权。创建/删除逻辑库和删除云资源不属于默认步骤；测试结束后的远程重置由用户按本次测试安排完成。
