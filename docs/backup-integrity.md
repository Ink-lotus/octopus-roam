# 备份导入与完整性检查

导入保留合法空库恢复、无冲突增量和兼容快照重放。数字 ID 或名称相同不能证明是同一实体；冲突不能安全解释时，整次拒绝，保留导入前的业务数据和关联。本变更不新增 UUID、跨实例身份或全图 ID 重映射，也不会猜测恢复已经覆盖的凭据、成员或统计。

## 接受与冲突规则

现有产品内容版本 `1000`～`1004`、无产品标识的上游 `0` 和 `5` 继续使用原接受矩阵；未知产品、未知版本及无标识 `6` 仍拒绝。功能字段遵守各自最早支持版本。旧字段先补默认值并规范化，再比较持久化内容；运行时状态和统计不作为实体身份。

备份必须能独立解释全部引用。只包含成员却缺少其授权、只包含 API Key 统计却缺少 API Key 等输入会拒绝，不能用本地碰巧同号的行补全。正整数实体 ID、0～23 小时、固定总统计 ID、唯一业务键、日期、统计值、授权两侧渠道及当前成员归属均需合法。当前成员 `0` 表示未指定。非空 ORM 嵌套关联会拒绝，持久化行必须位于备份顶层集合。

| 表 | 主键 / 业务唯一键 | 同主键重放 |
| --- | --- | --- |
| `channels` | ID / 名称 | 配置相同；保留本地启用、跟随全局刷新及并发限制，导入统计 |
| `channel_keys` | ID / 渠道与名称 | 渠道、名称和凭据正文相同；导入启用状态与统计 |
| `channel_models` | ID / 渠道与模型名 | 渠道和名称相同；导入统计 |
| `channel_grants` | ID / 模型与 Key | 两侧引用及协议相同，两侧必须属于同渠道 |
| `groups` | ID / 名称 | 名称、模式、匹配方式、Relay 配置相同；保留本地分类和当前成员，输入及本地选择各自校验归属 |
| `group_items` | ID / 分组与授权 | 两侧引用相同；保留本地优先级 |
| `api_keys` | ID | 凭据、名称及其他持久化配置相同；保留本地启用状态 |
| `webhook_endpoints` | ID | 规范化后的投递配置相同；导入启用状态 |
| `group_categories` | ID / 规范化名称 | 继续按规范化名称归并、保留本地显示名称；先预留可用输入 ID，再为冲突分配新 ID，映射分组引用 |
| `settings`、`llm_infos` | 设置键、规范化模型名 | 校验后按业务键导入；退役设置继续过滤 |
| 统计表 | 总统计 ID、日期、小时、API Key ID | 校验后覆盖指定业务键；API Key 统计须对应已确认兼容的父实体 |

不同 ID 命中同一业务唯一键时，SQLite、MySQL 和 PostgreSQL 均拒绝。数据库自己的大小写、重音和排序规则参与比较；数据库认为相等的另一 ID 或另一字符串主键拼写不会被误覆盖。实体使用明确插入和定向列更新，不使用 MySQL 无法限定冲突目标的盲目 upsert。报表里的 `rows_affected` 为逻辑接受的写入计数，不能用于证明数据完整性。

这会收紧旧增量行为：渠道改名、地址或 Header 改动、换 Key、授权换父、同 ID 成员换组等旧快照，可能从“导入成功”变成拒绝。此时应先保留独立副本，在隔离环境核对来源。不能通过反复导入拼接两个冲突快照。合法旧快照在空库中仍可恢复；自动合并冲突快照需要另行设计。

## 事务、缓存和错误

导入前先验证输入；事务内锁定相关表或主键范围，再检查本地图、冲突及预期组合图。待落库统计在同一事务内写入；备份覆盖的统计键直接使用备份值，避免空库缓存或首次请求统计提前插入同一主键。失败保留原缓存和 dirty 标记。提交前重读完整快照，验证关联及实际落库字段，缺行、触发器意外改值或后续 SQL 失败都会回滚；PostgreSQL 的费用 `real` 列按实际 32 位浮点存储精度比较。

PostgreSQL 使用表锁，MySQL 使用 `REPEATABLE READ` 下的完整主键范围锁，SQLite 取得写保留锁。唯一键、死锁、超时或外部事务竞争导致失败时，整次导入结束，不自动重放。序列允许产生安全空洞；PostgreSQL 的非事务序列副作用不能被描述为逐字节回滚。

进程内遵守 `groupMutationMu → channelRefreshCommitMu → groupWriteMu → backupAuxMu → backupStatsMu → backupCacheMu` 的锁顺序。网络探测期间不持这些提交锁；旧探测结果须通过刷新版本检查才能提交。导入使用事务里取得的完整快照发布缓存，再更新 Relay 和 SSE；失败不发布成功快照。Cooldown 通知在 op 写锁释放后调用。

| HTTP 状态 | 含义与处理 |
| --- | --- |
| `400` | 格式、值或备份图非法，未导入；修正输入 |
| `409` | 与本地身份、唯一键、数据库排序规则或关系冲突，未导入；按表、ID 和原因核对来源 |
| `500` | 事务或写入失败，业务数据未提交；排查数据库条件后再处理 |
| `503` | 事务已提交，但完整缓存发布失败；转发及相关配置/统计写入暂停。不要重复导入，保留数据库后重启服务，确认缓存初始化成功 |

大小限制继续返回 `413`，已有备份操作占用时返回 `429`。错误不回显凭据、Header 正文、Token 或连接信息；解析错误也不回显非法字段值。前端保留可读的导入错误，成功及提交后失败都会使相关查询重新读取状态。

转发在实际发送前再次检查授权及配置；已经发送的请求按原生命周期完成。此处不增加多副本支持：外部 SQL / 其他进程的写入受本次事务锁保护，但提交后的跨进程缓存一致性没有新增保证。维护或诊断应使用独立副本，不能把只读快照视为持续监控。

## 已有错配数据

Key / 模型跨渠道的授权不可用于转发。分组保留原成员并显示 `unavailable_reason`（实体 ID 和异常原因）；读取渠道编辑副本、普通保存和自动刷新会明确拒绝相关错配，防止“读取时漏成员，保存时顺带删除”。不相关的健康渠道继续允许维护。

结构审计可以发现缺失引用、跨渠道授权、跨组当前成员、非法主键及错误自增结构。已经被同渠道覆盖的 Key、已经删除的成员、落在合法小时内却来源错误的统计，通常无法仅凭现库判断，更不能自动移位、求和或重建。必须与可信的独立旧备份比较。

## 真正只读的诊断

使用新命令 `db-audit`，不要用 `db-check --connect` 做只读审计；后者会初始化数据库、运行迁移并写入设置。

```powershell
.\octopus-roam.exe db-audit --sqlite-path 'D:\isolated-copy\octopus-roam.db'
.\octopus-roam.exe db-audit --profile 'D:\isolated-copy\db-profiles.json' --alias '<test-profile>'
```

SQLite 路径必须已存在。命令独立打开只读连接，使用只读事务；不调用应用初始化、迁移、缓存初始化、设置补齐或序列修复，不执行 `nextval`。服务器数据库沿用 profile 的 TLS 配置。输出仅有阶段、各表计数、表名/实体 ID/固定异常码和诊断限制，不输出连接信息或配置正文。

完整且无异常时退出 `0`；发现异常、连接或结构不足时退出非 `0`。`complete=false` 表示没有完成整个审计，不能当作无问题。审计本身不改变表结构、业务行、迁移记录和序列状态；SQLite 正在运行时仍应遵守其备份及 WAL 复制规则，不把单个文件的随意复制当作完整快照。

已发布备份格式保持原样。新导出使用 1004 携带遗留小时归档；迁移 18、显式旧备份转换、空库恢复及审计规则见[遗留小时统计恢复](hourly-statistics-recovery.md)。归档不推断或修复旧损失。迁移 16/17 的升级与统计语义继续适用；恢复旧程序应配合升级前完整副本，不假定可直接降级读取新 schema。平台与正式发布验收继续遵守[发布门禁](release-ci.md)和[支持矩阵](support.md)。
