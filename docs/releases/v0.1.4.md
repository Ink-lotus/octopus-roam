# Octopus Roam v0.1.4

本版修复旧版遗留小时统计越界导致 v0.1.3 升级后无法启动的问题，适用于 Windows amd64 原生程序和 Linux amd64 Docker / Compose 的 SQLite 部署。升级前停止服务，保留旧程序、配置和完整数据目录；已启动失败的实例也应先保留原库及日志。

## 小时统计归档

旧版把小时整数主键设为自增。保存午夜 `Hour=0` 时可能生成递增编号，多次保存形成历史累计快照。v0.1.3 的迁移 17 修正结构但保留了越界行，随后启动校验报 `stats_hourly hour 24 must be between 0 and 23`。

- 保留迁移 17，新增迁移 18。未升级的旧库及已完成迁移 17、但启动失败的库均可进入修复流程。
- SQLite 中 `hour >= 24` 的行先写入独立归档，保留原小时、日期、全部指标及原始存储类型；回读核验后，在同一个事务中从活动统计表隔离并记录迁移成功。
- 不将异常小时归零、取模或求和。合法小时、总统计、每日及 API Key 统计、凭据和业务配置保持原值；归档不进入图表或统计累加。合法范围内可能存在的历史错位值无法仅凭现库辨认，本版不猜测修复。
- 归档、核验或写入失败会回滚该数据事务并报告原因。相关自定义触发器、外键、未知列或损坏归档会阻止自动处理；负数小时及其他非法数据仍拒绝。先前成功的迁移继续保留，整次跨版本升级不是单一事务。

自动隔离仅用于 SQLite。MySQL/PostgreSQL 仍为实验性范围，遇到此类越界记录会明确拒绝，需单独审查。

## 备份、旧备份转换与审计

新导出内容为 `octopus-roam` / **1004**，加密容器仍为 **1**。完整加密备份包含 `stats_hourly_archives`，支持空库恢复、重启校验及幂等导入。启动、导出、导入和只读 `db-audit` 均验证归档内容摘要；非法输入、身份冲突和引用完整性保护继续生效。

普通导入继续拒绝活动小时表中的越界行。对本产品 **1000～1003** 的旧加密备份，新增显式离线命令 `backup-convert-hourly`，通过 `--input`、`--output`、`--password-env` 和 `--archive-legacy-hours` 将可识别的遗留小时转入 1004 归档。命令不打开数据库、不覆盖输入或已有输出；保留原文件，并先在隔离空实例核验转换后的恢复结果。密码通过专用环境变量提供，不写入命令行或日志。

1004 须由 v0.1.4 或后续兼容程序恢复；旧程序会拒绝，不能手改版本号绕过。旧 JSON 无法还原导出前 SQLite 的 NULL 或存储类型，转换归档明确记录备份来源。详见[小时统计归档与恢复](https://github.com/Ink-lotus/octopus-roam/blob/v0.1.4/docs/hourly-statistics-recovery.md)和[备份完整性合同](https://github.com/Ink-lotus/octopus-roam/blob/v0.1.4/docs/backup-integrity.md)。

## 升级与交付

Windows amd64 原生程序 + SQLite，以及 Linux amd64 宿主上的 Docker Engine / amd64 镜像 + SQLite（含 Compose）为正式支持目标。WSL2 / WSL Containers 为预期兼容；Linux 原生、其他架构、macOS、Android 及其他数据库保持既有实验性或范围外状态。

发布交付 11 个程序 ZIP、四架构镜像、对应源码、原始声明、安装/重建说明及校验和，绑定准确 commit 和同一提交的本说明。保留固定工具、完整 CI 和双平台实际产物验收，结果以对应发布记录为准；v0.1.3 的标签和已发布附件保留原样。

在隔离的完整副本上先核验迁移、合法数据保持、归档、正常启停和空库备份恢复，再更新实际实例。无法启动的 v0.1.3 不应通过删除校验强行导出；保存停机后的完整数据目录即可准备升级演练。从 v0.1.0 的 Windows 旧布局首次迁移仍须同时手动更新 exe 与 cmd。回滚使用旧程序配升级前完整副本，会失去副本之后新增的数据；不承诺旧程序读取新数据库。具体步骤见[升级说明](https://github.com/Ink-lotus/octopus-roam/blob/v0.1.4/docs/upgrade-r1.md)。
