# Octopus Roam v0.1.6

本版增加可视化模型过滤、Key 级自定义冷却和规则 Webhook 通知，并修复旧 Webhook 模板的配置兼容性。

## 可视化模型过滤

- 全局设置与渠道高级设置共用编辑弹窗，支持保留/排除、等于/开头/结尾/包含匹配及 AND/OR 条件。
- 既有手写表达式保留原文，通过“编辑表达式”显式修改。无法还原为条件行时，可“清空并使用可视化编辑”；只修改弹窗中的待保存值，取消保留原值。
- 渠道高级设置和全局设置页的外部表达式预览最小一行，随内容增高，最大 144px，超出后内部滚动。弹窗继续显示可视化条件行。
- 全局保存等待设置成功；渠道应用先更新表单中的待保存值，随渠道保存提交。后端继续使用既有 `model_filter` / `match_regex` 正则。实际模型列表预览和样例测试未包含在本版。

## Key 冷却与规则通知

- 自定义规则增加 Key 作用域，覆盖同一渠道中该 Key 的全部模型；其他 Key 不受该规则影响。模型级和渠道级规则继续生效。
- 规则可开启 `notify_webhook`。旧规则缺少该字段时默认关闭；新一轮冷却触发通知，活动冷却期间延长截止时间不重复通知。
- 规则配置随渠道持久化和备份；活动倒计时重启清空，不进入备份。

## Webhook 与版本信息

Webhook 配置校验继续使用既有 `failure` 样例，旧自定义模板可正常创建、编辑、禁用和恢复。实际发送前仍校验最终 JSON。旧模板需要接收 `cooldown` 事件时，应添加能生成有效 JSON 的对应分支；默认新模板已经支持。

版本信息页移除“可从 Octopus Roam 发布页手动安装，或按容器升级说明替换镜像。”提示链接。安装和升级步骤见[升级说明](../upgrade-r1.md)。

## Windows 启动稳定性

修复 Windows 启动时，状态文件被短暂读取可能导致原子替换失败、程序退出的问题。对可能由文件共享引起的替换错误进行最多约 2 秒的重试；持续占用或权限不足仍明确报错，保留原状态文件。

## 备份兼容与升级

| 导出内容 | 内容版本 |
| --- | --- |
| 未使用 Key 作用域或规则通知，且没有格式 2 小时归档 | 1004 |
| 未使用扩展冷却，包含 MySQL/PostgreSQL 格式 2 小时归档 | 1005 |
| 任一规则使用 Key 作用域或开启 `notify_webhook`，可同时包含格式 1/2 小时归档 | 1006 |

加密容器仍为版本 1。v0.1.6 接受本产品内容 1000～1006，保留无产品标识上游 0/5 的接受范围；无标识 6 和未知身份继续拒绝。旧规则的通知开关默认关闭。重复导入与配置冲突仍遵守[备份完整性合同](../backup-integrity.md)，小时归档语义见[小时统计恢复](../hourly-statistics-recovery.md)。

1004 需要 v0.1.4 或后续兼容程序，1005 需要 v0.1.5 或后续兼容程序，1006 需要 v0.1.6 或后续兼容程序。v0.1.5 及更早程序不能恢复 1006，不能通过改版本号降级备份。升级前正常停止并保留旧程序、配置和完整数据库副本；回滚使用该副本，会丢失升级后的新增数据，也不承诺旧程序直接读取升级后的数据库。

## 支持与发布验收

正式支持 Windows amd64 原生程序 + SQLite，以及 Linux amd64 宿主上的 Docker Engine / Linux amd64 镜像 + SQLite，包含 Compose。WSL2 / WSL Containers 为预期兼容；Linux 原生、其他架构、macOS、Android、MySQL/PostgreSQL 等保持[当前支持矩阵](../support.md)中的状态。

本版真实 v0.1.5→v0.1.6 升级、正常启停、持久化和备份恢复须使用本次实际 ZIP/镜像；Linux 另验证数据卷权限、容器重建及 Compose。最终提交、说明原字节与摘要、完整 11 ZIP/四架构镜像、来源/许可材料和平台结果按[发布合同](../release-ci.md)绑定。开发阶段检查不能替代这批产物的应用验收。
