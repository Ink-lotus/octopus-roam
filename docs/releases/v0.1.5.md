# Octopus Roam v0.1.5

本版补齐 MySQL/PostgreSQL 中遗留小时统计的迁移处理。v0.1.4 的自动隔离仅覆盖 SQLite；仍有 `hour >= 24` 行的 MySQL/PostgreSQL 数据库使用 v0.1.4 时会在启动校验中继续失败，v0.1.5 增加了对应归档路径。

## 小时统计迁移

保留迁移 17 和迁移 18 的版本号。迁移 18 在 AutoMigrate 与迁移 16 后运行；未升级的旧库，以及迁移 17 已成功但小时校验失败的库，均会进入迁移流程。SQLite 原有格式 1 行为和归档摘要保持不变；MySQL/PostgreSQL 新增格式 2 归档，记录数据库来源及每列声明的 SQL 类型和值。

迁移只归档 `hour >= 24` 的小时行，保留原小时、日期、指标、NULL、整数、文本字节和浮点位；不把历史累计快照归零、取模、移位或合并。合法小时、其他统计和业务配置不变。归档写入、逐行回读、源行复核、活动表隔离与迁移成功记录在同一数据事务提交；失败时回滚并保留可重试状态。自定义触发器、外键、未知列、未支持类型及不安全表结构会导致迁移明确失败，不会跳过检查或猜测修复。

MySQL 要求小时表、归档表和迁移记录表均为 InnoDB，事务隔离为 REPEATABLE READ 或 SERIALIZABLE，并要求迁移连接能够完整检查触发器元数据和 InnoDB 外键元数据；后者需要经审查的 `PROCESS` 元数据权限。PostgreSQL 会检查规则、触发器、外键、RLS、分区和继承，并要求连接可锁定相关表。权限或 schema 不满足时，迁移保留数据并报错，由管理员审查处理；应用不会自动扩大数据库账号权限。

MySQL/PostgreSQL 与外部数据库仍在正式支持范围外。本版增加对应迁移和备份兼容行为，不扩大正式支持组合。正式支持目标仍为 Windows amd64 原生程序 + SQLite，以及 Linux amd64 Docker Engine / Compose 镜像 + SQLite。实际发布和平台验收结果绑定本版最终 commit 与实际产物，见[当前支持矩阵](../support.md)和[发布门禁](../release-ci.md)。

## 加密备份兼容

只含格式 1 小时归档时继续导出 `octopus-roam / 1004`；含 MySQL/PostgreSQL 格式 2 归档时导出 `1005`。加密容器仍为版本 1。新程序接受本产品 1000～1005 及已审计的无标识上游 0/5；旧程序不支持 1005，应使用兼容新版本恢复。跨数据库恢复保留归档证据，不将归档行重新写入活动小时表。

本产品 1000～1003 旧备份仍须显式通过离线 `backup-convert-hourly` 转换为 1004；转换器不打开数据库、不覆盖原文件，也不推断丢失的 SQLite 存储类型。完整升级、恢复与失败回滚步骤见[小时统计恢复说明](../hourly-statistics-recovery.md)及[升级说明](../upgrade-r1.md)。

## Codex 模型目录默认开启

`codex_catalog.enabled` 默认值由 `false` 改为 `true`；新部署以及未写该字段的已有配置在重启后默认开启目录接口。已显式配置 `enabled: false` 的实例继续关闭；`OCTOPUS_ROAM_CODEX_CATALOG_ENABLED=false` 也可覆盖配置并关闭。配置加载不会改写已有配置文件。Windows 兼容启动脚本创建的新配置同时写明 `enabled: true`、`use_proxy: false`。

`use_proxy` 仍默认关闭。API Key 鉴权、分组和模型权限过滤保持；只有收到目录请求时才按客户端版本获取 GitHub 快照。Codex 客户端仍须配置 `model_catalog_url`；网关默认启用不自动更改客户端配置。接入与关闭方法见 [Codex 目录说明](../codex-catalog.md)。
