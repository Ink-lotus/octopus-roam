# Octopus Roam v0.1.1

本说明对应 v0.1.1 的源码与发布准备。功能包已完成；完整版本回归、正式材料、候选产物和 Windows / WSL Containers 的真实升级验收仍需完成，当前没有 v0.1.1 正式 Release。实际交付日期、准确 commit、下载哈希和镜像摘要以最终发布记录为准。

## 本版变化

- **共享批量模型刷新。** 渠道页和分组页共用同一个刷新任务和进度，切页后继续执行，重复点击不重入。批量任务只选择启用渠道；开始处理及实际探测前复核，途中禁用、删除或正在刷新者正常跳过。分组搜索和平台分类筛选不缩小刷新范围。显式单渠道刷新保留原有行为；刷新继续遵守逐 Key、原子提交、成功空列表及渠道自动添加分组成员偏好。已发出的请求不能撤回，页面重载也不恢复浏览器中的批量任务。
- **隐私及凭据脱敏整体退出。** 移除隐私开关、规则、预览、诊断脱敏和固定凭据掩码。配置编辑与转发使用实际保存值，日志、按需诊断和 Webhook 在各自原有采集范围内保留原值。旧隐私设置被忽略，兼容旧备份仍可导入，新备份不再导出这些设置；历史日志不重写，已替换的内容不能复原。旧管理操作在认证后返回 HTTP 410。登录/API Key 鉴权及备份加密继续独立生效。
- **渠道自定义冷却规则。** 在渠道高级设置中手动添加错误码、关键词、秒数和模型级/渠道级范围。新建渠道、旧数据库升级及缺字段的旧备份默认空列表，不预置规则；无规则或未命中时沿用原有重试和成员退避。错误码精确匹配 HTTP 状态或上游 code/type，关键词按普通文本包含匹配、忽略英文字母大小写；至少填写一项，两项同时填写为 AND。秒数为 `1..2147483647` 的整数，不支持正则或脚本。
- **自定义平台分类。** 为模型分组创建、改名、删除一层分类，并手动选择归属；不会按供应商、模型名或渠道地址自动分类。旧分组默认未分类；删除分类只解除归属，保留分组及成员。分类与归属保存在服务端，筛选和折叠为浏览器视图偏好；支持搜索、名称排序、筛选后计数、空分类管理及列表虚拟化。分类变化不改变路由优先级、失败计数、成员顺序、手动选择或冷却状态。
- **已有 Windows 原生运行与更新能力。** 当前程序使用单个 cmd 菜单入口和 exe 原生启停、登录自启管理及更新助手。旧 v0.1.0 包到新原生布局的首次迁移需要手动更新 exe 和 cmd；新助手再次更新及失败恢复须用本版最终程序独立验收。
- **选择性上游更新。** 纳入已验收的三种文本协议普通/流式兼容修复、九方向流式启动事件缓冲、工具身份处理及日志优化。已向客户端提交的响应仍不重放；本版不扩展生图、WebSocket 或新的客户端能力。

## 冷却的作用范围与生命周期

模型级按“渠道 ID + 实际上游模型名”共享，覆盖该渠道中引用同一模型的 Key、协议授权和所有分组；其他模型和其他渠道同名模型不受影响。渠道级覆盖整个渠道的全部模型、Key、授权及引用分组。

规则只处理真实 Relay 上游失败，包括 HTTP 200 内的流式错误；正常输出、prompt、本地校验、客户端取消和模型列表探测不触发。关键词匹配的是最多 4096 UTF-8 字节的错误消息。多条规则、模型级、渠道级及既有成员退避共同生效时取较晚截止时间；成功、模型刷新和 Retry-After 不缩短用户设置的时长。

手动模式等待所选目标恢复或用户切换；故障转移可选其他未阻断成员，全部阻断时等待。等待释放渠道并发额度，不计实际发送次数，并响应取消与切换。现有“解除成员冷却”操作不清除跨分组共享的规则冷却。规则或出站连接/凭据变更会使旧规则状态失效，迟到旧请求不能重新建立它；展示名称、分类及单纯刷新不解除冷却。规则配置持久化，倒计时仅在进程内，重启清空且不进入备份。

## 数据与备份

本版新增迁移 014（渠道规则）和 015（平台分类及归属）。备份产品标识仍为 `octopus-roam`，内容版本统一为 **1001**，加密容器保持 **1**。同一份加密备份包含规则、分类集合及分组归属；运行冷却、缓存版本和 SSE 状态不导出。

新程序接受本产品 1000 / 1001，以及既有无产品标识的上游 0 / 5；无标识 6、其他产品和未知版本继续拒绝。旧格式缺规则为空、缺分类为未分类，不能用旧版本标识夹带非空的新字段。1001 中非法规则、分类、引用或显式 null 数组使整次导入失败，不留下部分数据。

导入继续采用增量语义：同 ID 已有渠道的规则、已有分组的归属保持本地配置。分类按规范化名称合并，ID 冲突时为新分类分配本地 ID 并映射归属。空库恢复才能完整还原备份中的配置；增量导入不等于覆盖整个数据库。1001 备份不能用于向 v0.1.0 降级恢复。

## 升级、回滚与支持范围

升级前正常停止旧服务，保存旧程序、配置和完整数据快照；SQLite 应保留完整数据目录及必要 WAL 文件。首次从 v0.1.0 的 PowerShell 支持文件布局迁移时，同时手动替换 exe 与 cmd，并只处理属于该部署的旧登录快捷方式；详见[升级步骤](../upgrade-r1.md)和[Windows 布局迁移](../local-deployment.md#从旧脚本布局迁移)。旧版在线更新器不能直接接受新布局。

回滚使用旧程序和升级前完整快照；不承诺旧程序直接读取迁移后的数据库。恢复旧快照会丢失升级后的新增数据。保留失败现场和原镜像，不能仅把旧程序或旧镜像接回新数据库作为可靠回滚。

正式支持范围沿用两个组合：Windows amd64 原生程序 / SQLite，以及 Windows / WSL Containers 3.0.3.0 / Linux amd64 镜像 / SQLite。本版最终程序仍需完成这两个组合的真实升级验收。其他原生平台、镜像架构、MySQL/PostgreSQL、Docker Engine/Compose 和反向代理等维持实验性或范围外状态。发布合同仍要求完整 11 个 ZIP、四架构镜像、对应源码和声明；可构建不等于正式支持。

已知限制继续包括 [BUG-001](../known-bugs.md)：个别兼容渠道的 Anthropic 模型列表探测可能报告 401，本版没有增加鉴权回退。最终依赖来源、许可证 CSV、原始声明、复建及 LGPL 再链接材料须按本版准确输入重新生成或经差异审查复用；旧程序与旧验收不替代本版最终产物证据。

## 发布输入

正式合同仅接受 `v0.1.1` 或 `v0.1.1-rc.N`（N 为无前导零正整数）。源码版本注释、前端 package 版本、构建注入和本说明首行必须一致。所有发布阶段取准确获审查 commit 中本文件的原始 Git blob，记录 `release_notes_path` 和 `release_notes_sha256`；交付的 `RELEASE-NOTES.md` 保持相同字节。候选转正式需要重新审查、绑定、构建及验收，不能仅改产物名称。流程见[发布合同](../release-ci.md)及[材料与验收入口](../release-materials.md)。
