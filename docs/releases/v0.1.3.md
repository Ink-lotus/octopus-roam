# Octopus Roam v0.1.3

本版修复备份导入和统计完整性、Responses 历史清理与流式响应长度，并提供按 Codex 客户端版本读取的模型目录。升级前正常停止服务，保留旧程序、配置和完整数据副本。

## 备份与数据完整性

- 修复 PostgreSQL 显式 ID 导入后序列落后导致首次保存或新增失败的问题。迁移 16 同步九类实体序列，保留已领先的安全值、序列参数和事务保护；迁移后重建连接池，避免旧 prepared statement 缓存失效。
- 迁移 17 修正小时、总统计、API Key 统计和迁移编号这些业务主键的错误自增结构，保留现有行、索引和关联。小时 0 正确保留，正常保存和停止不再遗漏跨午夜尚未落库的统计；不猜测移动或修复历史错位值。
- 导入在写入前和同一事务内检查完整引用图、实体身份、唯一键与关联。合法空库恢复、无冲突增量和兼容快照重放继续支持；冲突返回 409 并整次拒绝。不同快照中同 ID 的配置、凭据或归属不兼容时，不再静默覆盖或拼接。
- 导入提交后只发布完整缓存快照。若数据库已提交但缓存发布失败，返回 503 并暂停转发及相关写入；保留数据库后重启，不重复导入。事务提交前失败保留原业务数据。
- 已有跨渠道授权或跨组成员错配会显示不可用原因，相关读取、保存和刷新受到保护。新增只读 `db-audit`，用于检查结构和引用；它不运行迁移、补设置、改序列或自动修复数据。

备份继续导出 `octopus-roam` 内容 **1003**、加密容器 **1**，接受本产品 1000～1003 和已审计的无标识上游 0/5；无标识 6、未知身份和不合法内容继续拒绝。完整冲突规则见[备份完整性说明](https://github.com/Ink-lotus/octopus-roam/blob/v0.1.3/docs/backup-integrity.md)。

## Responses 历史与流式响应

- 默认关闭的 `strip_responses_history` 开关开启后，只删除顶层 `previous_response_id` 和 `input` 第一层的 `item_reference`。保留 `agent_message`、`compaction`、`reasoning`、消息和工具项的 ID、密文、字段值、类型和顺序，也保留 `include` 原值。
- 清理在渠道参数覆盖之后执行，覆盖最终发往 Responses 的透传和协议转换请求；一次渠道尝试的清理不污染后续尝试的原始历史。
- 修复 Relay 重新编码 SSE 后仍携带上游旧 `Content-Length` 的问题，避免完整流被客户端判为长度不足。回归覆盖 Chat Completions、Responses 和 Anthropic Messages，普通 JSON 响应保留对照。

客户端仍须提供必要历史；保留密文不保证另一个账号或上游能够解密，也不能恢复已经丢失的内容。开关名称、默认值和保存字段不变。详见[历史清理说明](https://github.com/Ink-lotus/octopus-roam/blob/v0.1.3/docs/responses-history-cleanup.md)。

## Codex 模型目录

新增 `GET /codex/models?client_version=<major.minor.patch>`。`codex_catalog.enabled` 与 `codex_catalog.use_proxy` 均默认 false，通过配置和重启生效。网关匿名读取：

```text
https://raw.githubusercontent.com/openai/codex/rust-v<client_version>/codex-rs/models-manager/models.json
```

入口保留现有 API Key 鉴权、分组和 `supported_models` 过滤；目录不代表实际推理权限或可用性。保留完整官方元数据、未知字段及 `auto_review_model_override` 原值，不补模型、不合成 `origin`，不回退其他版本、main/latest 或旧在线来源。缓存按版本隔离，每次重新过滤当前权限；过期取源失败返回错误。

实际 CLI 验收范围仅为原生 Codex **0.169.0**：Sol/Astra 均实际使用 Luna/low 审核，包含五类负面条件、重启和工具后续轮次。缺 Luna、404/429 采用明确的合成目录响应；权限收紧和取源不可达来自真实网关，实际推理与合成 fixture 分别记录。0.167.0/0.168.0 只完成快照取源验证。快照身份与网关源码/产物分别记录，同标签内容变化须重新核对。配置和错误处理见[接入说明](https://github.com/Ink-lotus/octopus-roam/blob/v0.1.3/docs/codex-catalog.md)。

## Windows 与构建

- 原生更新助手在恢复旧程序时，对 Windows 临时访问/共享/锁冲突执行有界重试；其他错误和持续占用仍明确失败，保留校验、路径保护及回滚规则。
- 前端固定 Tailwind 扫描范围并统一 gzip 头，避免构建目录位置和平台差异引入额外样式或不同资源字节。
- 发布合同绑定本版完整源码 SHA 与同一提交的说明 Git blob，交付 11 个程序 ZIP、四架构镜像、对应源码、原始声明、安装/复建说明和摘要。工具固定 Go 1.27.3、Node 24.18.0、pnpm 11.15.1、Python 3.14.6、actionlint 1.7.7、NDK r28c。

## 支持与升级

正式支持 Windows amd64 原生程序 + SQLite，以及 Linux amd64 宿主上的 Docker Engine / amd64 镜像 + SQLite，包含 Compose。首次 Linux 开发产物应用验收已在累计提交 `9a7ed524bf763bc776ef291a0998aeb715700ad4` 完成；本版候选和正式发布 run 仍须分别核对实际产物并完成规定验收，详见[当前支持与证据](https://github.com/Ink-lotus/octopus-roam/blob/v0.1.3/docs/support.md)和[发布合同](https://github.com/Ink-lotus/octopus-roam/blob/v0.1.3/docs/release-ci.md)。

WSL2 / WSL Containers 为预期兼容环境，不再单列必验项。Windows 实际退出再登录仅在登录自启相关改动或异常时触发；保留菜单和原生更新助手检查。客户端按原生 Codex CLI 与 HTTP/SSE 验收，不设置独立 Paseo 现场门禁。Linux 原生、其他架构、macOS/Android 继续实验性；MySQL/PostgreSQL 和其他部署组合的既有测试保留，不扩大正式支持范围。

从真实 v0.1.2 升级时，迁移按 before → AutoMigrate → after 执行，不能按编号简单重排。已有兼容开关值保持；首次从 v0.1.0 旧布局迁移仍须手动同时更新 exe 与 cmd。完整恢复使用空实例；回滚使用旧程序配升级前完整副本，会失去副本之后新增的数据，不承诺旧程序直接读取新 schema。详见[升级步骤](https://github.com/Ink-lotus/octopus-roam/blob/v0.1.3/docs/upgrade-r1.md)。

保留历史诊断限制：B04 首次 Relay race 超时诱因和旧 helper 的当时句柄持有者尚未完全查明；C02 首次进程记录文件占用者仍未知，产品 `desktop.WriteJSON` 未修改。后续再次出现异常时继续调查，本版通过记录不代表这些历史原因已查清。
