# R1 升级、备份与故障排查

Octopus Solo 从 bestruirui/octopus v0.13.6 分叉，S1 选择性吸收 v0.13.8。首个独立版本为 `v0.1.0`，编号降低不代表回退上游功能。当前 R1 仍在工作区验收，候选版与正式版发布尚未执行。

## 升级与回滚

当前已停用版本检查与一键更新，版本页提供手动升级链接。请从 [Octopus Solo Releases](https://github.com/Ink-lotus/octopus-solo/releases) 获取后续构建；自动升级及其产物校验流程需另行设计。独立镜像地址为 `ghcr.io/ink-lotus/octopus-solo`，目前尚未发布。

首次发布验收以全新安装、当前版本备份恢复和重启持久化为准，旧版本升级兼容不作为首发门槛。仓库外的本地运行目录安排见[本地部署说明](local-deployment.md)。以下升级步骤供后续版本使用。

1. 记录当前构建和配置，正常停止旧服务，让内存统计落盘。使用数据库原生工具或停机副本保留升级前数据库；SQLite 应保留完整数据目录，包括尚未检查点合并的 WAL 文件，勿只复制一个运行中的 `.db`。
2. 在隔离目录/数据库副本上启动新构建。旧数据库的编号迁移及 GORM AutoMigrate 会自动执行；R1 本次不新增数据库迁移。核对渠道、Key 启停、分组模式/当前成员、模型授权与请求转发。
3. 在设置页输入至少 12 个字符的备份口令，重复确认后导出 `.encrypted.json`。在另一个隔离实例中导入，确认可恢复后再切换业务实例。
4. 回滚时停止新服务，使用**升级前的构建和数据库副本**。新格式备份不能交给旧程序导入；增量 JSON 导入也不会删除现有多余记录，不能充当整库回滚。

SQLite 检查与临时实例验收结果见 [R1 记录](../plan/r1-result.md)。该记录保留当时的旧版本兼容验收口径；首次发布采用上面的新安装口径。当前环境没有 MySQL/PostgreSQL 实例；若首版声明支持这两种数据库，仍需验证其全新安装、读写及当前版本备份恢复。数据库迁移记录保留，不能通过删除记录或手改版本号冒充完成迁移。

## 加密备份

下载文件使用 scrypt 派生密钥和 AES-256-GCM 加密完整备份，包含可恢复的渠道 Key、客户端 API Key、Webhook 认证头及配置。口令不保存在服务器，也不能找回；它独立于登录密码。请单独保管口令，使用 HTTPS 传输。备份加密不改变业务数据库本身的存储方式。

备份包含渠道、凭据、模型、授权、分组、成员、模型价格、API Key、设置、Webhook 和统计。管理登录账号、迁移记录、内存路由状态、日志和刷新诊断不在 JSON 备份中；完整灾备仍需数据库和配置副本。

| 文件 | 导入行为 |
| --- | --- |
| 本产品加密容器 `version: 1`，内层 `octopus-solo` / `1000` | 提供正确口令后导入 |
| 本产品明文 `product: "octopus-solo"` / `version: 1000` | 可导入；正常 UI 导出只产生加密文件 |
| 无产品标识的上游 `0` / `5` | 保留裸 JSON、API 响应包裹及 multipart 导入 |
| 无标识 `6`（阶段 4/5 预发布格式） | 明确拒绝；用新构建打开原数据库后重新导出 |
| 外来标识、未知容器/内容版本、混合响应包裹 | 拒绝 |

只有旧 `6` 号 JSON、没有原数据库的情况下，本版本不提供直接恢复路径。不要手改版本号绕过身份检查。

导入采用增量语义：渠道、分组、成员和客户端 API Key 冲突时保留已有配置；渠道统计另行覆盖；渠道凭据、模型、授权、模型价格、设置、Webhook 及统计按原规则更新。新增记录的禁用状态被保留，已有渠道 Key 按备份覆盖启停状态。失效成员引用导致整次导入回滚，错误不会留下半份数据。

内层 JSON 上限 64 MiB，上传请求上限 96 MiB，单进程同时处理一个备份任务。超大实例使用原生数据库备份。错误口令或内容篡改返回同一错误；不会把解密失败的文件转当明文导入。

## 脚本接口变化

- 导出改为已认证的 `POST /api/v1/setting/export`，JSON 请求体 `{ "password": "<备份口令>" }`，响应为加密 JSON 下载。旧 `GET` 返回 `405`。
- 导入仍为已认证的 `POST /api/v1/setting/import`，multipart 字段 `file` 和 `password`；旧明文文件不需要口令，原有裸 JSON 上传继续支持。
- 口令不要放入 URL、日志、共享脚本或持久配置。导出/导入忙碌返回 `429`，超限返回 `413`，无效文件或口令返回 `400`。数据库写入失败返回通用 `500` 并回滚；若已导入但缓存重载失败，会明确提示重启服务。

## 配置默认值与操作规则

运行配置仍使用 `data/config.json` 或 `--config` 指定文件；环境变量前缀仍是 `OCTOPUS_`。新增产品设置保存于数据库，不能当成 config.json 字段。

| 配置 | 默认值 / 行为 |
| --- | --- |
| `channel_auto_update_enabled` | `false`，全局自动更新默认关闭 |
| `channel_auto_update_interval_minutes` | `1440`，可设置 1–10080 分钟 |
| `channel_auto_update_auto_add_groups` | `false`，不自动追加分组成员 |
| 渠道 `follow_global_auto_update` | 旧值缺省按 `true`；显式 `false` 保留 |
| 渠道 `max_concurrency` | `0` 不限；正数为跨 Key、跨分组共用额度 |
| 渠道 `allowed_protocols` | 缺省或 `0` 兼容全部现有协议（有效掩码 `14`） |
| 分组 `model_match_mode` | `keyword`；`exact` 完整匹配，均忽略大小写并按规则去首尾空格 |
| `webhook_manual_failure_threshold` | `10` |
| `webhook_failover_channel_threshold` | `3` |

全局 `group_route_defaults` 只设置路由策略。未勾选覆盖时只影响新分组；覆盖时保留已有分组的 `manual`/`failover` 模式、成员顺序与手动当前成员。默认固定重试间隔 3 秒，指数重试初始 1 秒、上限 600 秒；手动总尝试次数 `0` 表示不限；故障转移每成员 2 次、冷却 60 秒；非流式完整响应超时 120 秒、流式首事件超时 30 秒。旧 affinity 字段有效值为 `0`。

模型刷新所有 Key 成功后才提交；任一失败保留旧模型、授权和分组成员。成功返回空列表会清空模型及失效成员，但渠道和分组实体仍在。自动追加只作用于已有分组，严格匹配不会把带后缀的模型加进同名前缀分组。启用自动更新前应确认供应商模型列表可靠，成功空结果会影响后续路由。

## 日志与排障

请求状态：`running` 表示选路、排队或请求中；`committed` 表示首字节已交付，此后不能重试；`success` 为完整交付；`failed` 为失败结束；`canceled` 为客户端取消。渠道状态另分 `waiting`、`normal`、`error`。请求中日志置顶，筛选影响展示，不更改执行状态；SSE 断线后重新连接并刷新状态。

| 现象 | 检查与处理 |
| --- | --- |
| 刷新时 Key 失败 | 展开渠道刷新详情，检查该 Key、供应商地址和协议路径；旧模型保留。不要通过重复提交覆盖正在运行的刷新。 |
| 模型变为空 | 区分成功空结果与请求失败；检查全局/渠道正则过滤和供应商权限。补齐模型授权后重新同步已有分组。 |
| 请求并发排队 | 查看渠道占用/等待数；流式请求直到结束才释放额度。检查长流或取消情况，再按供应商额度调整上限。 |
| Webhook 失败 | 使用测试发送检查 URL、认证头、超时与目标端状态；诊断中敏感值脱敏。失败阈值通知与恢复通知各自去重。 |
| 备份口令错误或文件损坏 | 核对该文件的口令，含首尾空格；使用未修改的原文件。不能通过改变格式字段恢复。 |
| 导入后已有配置未变化 | 属增量冲突规则。完整替换/回滚使用隔离恢复或数据库副本。 |
| 隐藏的禁用渠道找不到 | 在渠道筛选中切到“全部”或“禁用”；筛选不删除渠道，也不改变备份内容。 |

加密格式与实现细节见 [加密设计](backup-encryption-design.md)，字段/迁移清单见 [迁移审计](../plan/r1-migration-audit.md)。
