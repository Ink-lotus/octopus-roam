# v0.1.1 升级、备份与故障排查

[v0.1.1](https://github.com/Ink-lotus/octopus-roam/releases/tag/v0.1.1) 已于 2026-11-08 正式发布。本版已整体移除隐私及凭据脱敏功能：设置页没有隐私开关、规则或预览入口；渠道和 Webhook 编辑先读取最新实际配置，未改字段按原值保存，显式修改或清空遵守原有业务校验，不识别历史掩码或猜测其原值。日志、按需诊断正文和通知在各自原有内容范围内使用原值，不新增请求 Header/Body 采集；历史日志中已替换的内容不能复原。

旧数据库中的 `privacy_protection_enabled` / `privacy_protection_rules` 行保持原样，启动与缓存忽略它们，不解析旧规则。含这两键的兼容旧备份可导入，新导出排除它们。旧 GET/POST `privacy-rules`、POST `privacy-preview` 和通用设置写入这两键，在管理员认证后返回 HTTP 410、`reason: feature_removed`；未认证仍返回 401。登录/API Key 鉴权与备份加密继续独立生效。

v0.1.1 新增迁移 014（渠道冷却规则）和 015（平台分类及分组归属）。旧渠道默认空规则，旧分组默认未分类；规则和分类共同使用备份内容 `octopus-roam` / **1001**，加密容器仍为 **1**。功能说明见 [v0.1.1 说明](releases/v0.1.1.md)。当前正式版本为 v0.1.1；本页说明从 v0.1.0 升级、备份与回滚的操作。

正式支持范围沿用 Windows amd64 + SQLite，以及 Windows / WSL Containers 3.0.3.0 / Linux amd64 镜像 + SQLite；其余构建和部署组合仍按[既有支持矩阵](support-v0.1.0.md)的实验性或范围外状态处理。本版的完整回归、数据兼容和这两个组合的真实 v0.1.0 升级验收已完成。

## 升级与回滚

版本页只检查 Octopus Roam 自己的发布源，不会查询或下载上游项目。公开版本从本仓库 Release 获取；本地开发版显示“开发或本地构建”，不会提供更新按钮。独立镜像地址为 `ghcr.io/ink-lotus/octopus-roam`；部署 v0.1.1 时使用准确的 `v0.1.1`（WSLc 使用 `v0.1.1-amd64`）或已核对的 digest，`latest` 随稳定版更新。程序与校验和从 [v0.1.1 Release](https://github.com/Ink-lotus/octopus-roam/releases/tag/v0.1.1) 下载。

稳定版只接受更高稳定版；官方 RC 接受更高 RC 或对应的稳定版。版本比较按数字段和 RC 序号进行，不能按字符串排序。更新查询、归档和 `SHA256SUMS` 来自同一个独立版本；归档会先下载到隔离临时目录，校验 HTTP 状态、大小、路径和哈希后才替换程序。配置、数据库和备份目录不会从归档写入。Windows 更新在当前进程正常退出后由隐藏的本地辅助进程替换 exe，并保留更新前程序和菜单支持文件备份；Linux/macOS 在同一安装目录内完成原子替换后重启。容器内不替换程序文件，按镜像标签升级并重启容器。

如果独立发布源没有版本、当前已是最新、平台不支持在线替换或当前是本地构建，设置页分别显示对应状态。请求失败和校验失败会保留原程序；更新接口需要管理员认证，接口返回“已校验并准备重启”只表示替换流程已排队，不能据此证明新程序已经启动。确认完成时，应重新登录并核对运行版本与本次接受的目标完全一致。本版原生助手的成功更新及失败恢复已完成验收。

本版已分别完成“真实正式 v0.1.0 程序和完整数据升级到本版”以及“本版程序使用原生助手再次更新/失败恢复”的验收。升级现有部署时，仍需按以下步骤核对自己的数据与运行状态。运行目录安排见[本地部署说明](local-deployment.md)。

1. 记录当前构建和配置，正常停止旧服务，让内存统计落盘。使用数据库原生工具或停机副本保留升级前数据库；SQLite 应保留完整数据目录，包括尚未检查点合并的 WAL 文件，勿只复制一个运行中的 `.db`。
2. 在隔离目录/数据库副本上启动新构建。编号迁移和 GORM AutoMigrate 会执行，014 补充空规则，015 增加分类及可空归属。核对渠道、Key 启停、模型授权、分组模式/当前成员、路由参数和统计；旧分组应为未分类，旧渠道不自动生成冷却规则。再次正常停止、重启后检查持久化。
3. 在设置页输入至少 12 个字符的备份口令，重复确认后导出 `.encrypted.json`。在另一个隔离实例中导入，确认可恢复后再切换业务实例。
4. 回滚时停止新服务，使用**升级前的构建、配置和完整数据库快照**。不承诺旧程序直接读取新数据库，1001 备份不能交给 v0.1.0 恢复；增量 JSON 导入也不会删除现有多余记录，不能充当整库回滚。恢复升级前快照会丢失升级后的新增数据。

本版兼容验收已覆盖规则与分类共同恢复、遗留隐私设置退役、失败无部分写入，以及真实旧程序拒绝 1001 且数据不变。数据库迁移记录保留，不能通过删除记录或手改版本号冒充完成迁移。MySQL/PostgreSQL 的已有功能和测试继续保留，未扩大正式支持范围。

## 从 v0.1.0 升级与容器升级

v0.1.1 Windows 程序采用原生菜单控制和更新助手；v0.1.0 仍使用旧版 PowerShell 布局。首次从旧版 PowerShell 布局切换到仅含 cmd 入口的新布局需要手动升级，旧版在线更新器不能识别新包；请按[本地迁移步骤](local-deployment.md#从旧脚本布局迁移)同时替换 exe 和 cmd，并处理属于该部署的旧登录快捷方式。

完成首次手动迁移后，新版 Windows amd64 非容器实例可使用原生更新助手。后续更新前重新查询版本，确认准确目标；遇到 409 时刷新版本信息后重新确认。接口回执中的目标和重启后的运行版本必须一致，刷新页面后还需确认前端版本。本版助手已通过实际更新及失败恢复验收。

稳定版本只选择更高稳定版本，不接受 RC；RC 可升级到更高 RC 或更高稳定版本。版本来源为[本仓库 Releases](https://github.com/Ink-lotus/octopus-roam/releases)，当前已发布稳定版为 v0.1.1，不应转而下载上游或把 RC 当作稳定版。

容器内的版本页提示按镜像升级。WSLc 3.0.3.0 的操作顺序如下：

1. 记录旧容器的准确镜像标签/digest、数据目录、端口和环境变量，导出加密备份。
2. 用 `wslc stop --time 30 <旧容器名>` 正常停止；将完整宿主数据目录复制到一个新的备份目录并核对副本。保留原容器和旧镜像。
3. 核对 v0.1.1 的发布材料后，用 `wslc pull ghcr.io/ink-lotus/octopus-roam:v0.1.1-amd64` 拉取并核对镜像身份。创建新名称的容器，保留原挂载、端口与必要环境变量；启动结构见 README 的 WSLc 小节，使用本次准确镜像标签。
4. 登录核对运行版本、设置、渠道、禁用状态和分组，正常停止/重启后再次核对。另用空数据目录验证当前加密备份恢复。
5. 新部署失败时先正常停止它，将升级前完整数据副本复制到新的恢复目录，并以旧镜像和该恢复目录新建容器。保留失败现场；仅将旧镜像连接已迁移目录不能作为可靠恢复。

Docker Engine/Compose 为首发范围外的参考部署。使用 Compose 时，先保留当前镜像标签/digest，导出加密备份，并正常停止容器后保存完整数据目录；同时保留现有 Compose 的挂载、环境变量与端口配置。在 `docker-compose.yml` 所在目录设置已发布的新标签：

```powershell
$env:OCTOPUS_ROAM_VERSION = 'v0.1.1'
docker compose pull octopus-roam
docker compose up -d octopus-roam
```

核对容器实际镜像 digest、页面运行版本和原有设置/渠道/分组，再验证持久化。正式版本更新 `latest`；部署仍建议固定版本或已核对的 digest，RC 不更新稳定标签。如果升级失败，先正常停止本次容器，按升级前镜像标签与升级前完整数据副本恢复；保留失败日志与原镜像，不删除数据卷。仅把旧镜像连接已被新版本迁移的数据目录不构成可靠回滚。

Linux 原生、macOS、Android 和其他架构镜像为实验性构建。MySQL/PostgreSQL、Docker Engine/Compose、外部数据库容器及反向代理等组合不在首发正式支持范围；已有证据和后续补验条件见[支持矩阵](support-v0.1.0.md)。

## 加密备份

下载文件使用 scrypt 派生密钥和 AES-256-GCM 加密完整备份，包含可恢复的渠道 Key、客户端 API Key、Webhook 认证头及配置。口令不保存在服务器，也不能找回；它独立于登录密码。请单独保管口令，使用 HTTPS 传输。备份加密不改变业务数据库本身的存储方式。

备份包含渠道（含冷却规则）、凭据、模型、授权、平台分类、分组归属、成员、模型价格、API Key、设置、Webhook 和统计。管理登录账号、迁移记录、内存路由/冷却状态、缓存/SSE 版本、日志和刷新诊断不在 JSON 备份中；完整灾备仍需数据库和配置副本。

| 文件 | 导入行为 |
| --- | --- |
| 本产品加密容器 `version: 1`，内层 `octopus-roam` / `1000` 或 `1001` | 提供正确口令并通过内容校验后导入；新导出为 1001 |
| 本产品明文 `product: "octopus-roam"` / `version: 1000` 或 `1001` | 可导入；正常 UI 导出只产生加密文件 |
| 无产品标识的上游 `0` / `5` | 保留裸 JSON、API 响应包裹及 multipart 导入 |
| 无标识 `6`（阶段 4/5 预发布格式） | 明确拒绝；用新构建打开原数据库后重新导出 |
| 外来标识、未知容器/内容版本、混合响应包裹 | 拒绝 |

只有旧 `6` 号 JSON、没有原数据库的情况下，本版本不提供直接恢复路径。不要手改版本号绕过身份检查。

导入采用增量语义：渠道、分组、成员和客户端 API Key 冲突时保留已有配置；渠道统计另行覆盖；渠道凭据、模型、授权、模型价格、设置、Webhook 及统计按原规则更新。新增记录的禁用状态被保留，已有渠道 Key 按备份覆盖启停状态。失效成员引用导致整次导入回滚，错误不会留下半份数据。

同 ID 已有渠道保留本地冷却规则，已有分组保留本地分类归属。分类按去除首尾空白、转小写后的名称归并；同名称复用本地分类，ID 冲突且名称不同则分配新 ID 并映射新分组归属。空库恢复才能完整还原备份配置，增量导入不能当作强制覆盖恢复。

1001 中规则或分类数组显式为 null、非法规则、重复/非法分类或悬空归属均拒绝，失败不产生部分写入。旧 1000 或上游 0/5 缺新字段时使用空规则/未分类，不能夹带非空新规则或分类；遗留隐私键只作退役过滤。内容 1001 不支持向 v0.1.0 降级恢复。

内层 JSON 上限 64 MiB，上传请求上限 96 MiB，单进程同时处理一个备份任务。超大实例使用原生数据库备份。错误口令或内容篡改返回同一错误；不会把解密失败的文件转当明文导入。

## 脚本接口变化

- 导出改为已认证的 `POST /api/v1/setting/export`，JSON 请求体 `{ "password": "<备份口令>" }`，响应为加密 JSON 下载。旧 `GET` 返回 `405`。
- 导入仍为已认证的 `POST /api/v1/setting/import`，multipart 字段 `file` 和 `password`；旧明文文件不需要口令，原有裸 JSON 上传继续支持。
- 口令不要放入 URL、日志、共享脚本或持久配置。导出/导入忙碌返回 `429`，超限返回 `413`，无效文件或口令返回 `400`。数据库写入失败返回通用 `500` 并回滚；若已导入但缓存重载失败，会明确提示重启服务。

## 配置默认值与操作规则

运行配置仍使用 `data/config.json` 或 `--config` 指定文件；环境变量前缀仍是 `OCTOPUS_ROAM_`。新增产品设置保存于数据库，不能当成 config.json 字段。

| 配置 | 默认值 / 行为 |
| --- | --- |
| `channel_auto_update_enabled` | `false`，全局自动更新默认关闭 |
| `channel_auto_update_interval_minutes` | `1440`，可设置 1–10080 分钟 |
| `channel_auto_update_auto_add_groups` | `false`，不自动追加分组成员 |
| 渠道 `follow_global_auto_update` | 旧值缺省按 `true`；显式 `false` 保留 |
| 渠道 `max_concurrency` | `0` 不限；正数为跨 Key、跨分组共用额度 |
| 渠道 `allowed_protocols` | 缺省或 `0` 兼容全部现有协议（有效掩码 `14`） |
| 渠道 `cooldown_rules` | 默认 `[]`，只在高级设置中手动添加；错误码/关键词双填为 AND，秒数 `1..2147483647`，模型级/渠道级跨分组共享 |
| 分组 `category_id` | 默认 null（未分类）；一层手动分类，删除分类仅解除归属 |
| 分组 `model_match_mode` | `keyword`；`exact` 完整匹配，均忽略大小写并按规则去首尾空格 |
| `webhook_manual_failure_threshold` | `10` |
| `webhook_failover_channel_threshold` | `3` |

全局 `group_route_defaults` 只设置路由策略。未勾选覆盖时只影响新分组；覆盖时保留已有分组的 `manual`/`failover` 模式、成员顺序与手动当前成员。新安装默认使用指数退避：初始 1 秒、每次翻倍，最大间隔默认 600 秒，可按需设为更长时间；选择固定模式时默认间隔为 3 秒。已有全局策略及分组的显式配置继续生效，旧配置缺少重试模式时仍按固定间隔处理。手动总尝试次数 `0` 表示不限；故障转移每成员 2 次、冷却 60 秒；非流式完整响应超时 120 秒、流式首事件超时 30 秒。旧 affinity 字段有效值为 `0`。

模型刷新所有 Key 成功后才提交；任一失败保留旧模型、授权和分组成员。成功返回空列表会清空模型及失效成员，但渠道和分组实体仍在。自动追加只作用于已有分组，严格匹配不会把带后缀的模型加进同名前缀分组。启用自动更新前应确认供应商模型列表可靠，成功空结果会影响后续路由。

两页批量刷新共享同一个任务，只选择启用渠道，实际探测前再次复核，禁用/删除/正在刷新者正常跳过。搜索与分类筛选不缩小任务范围；切页继续执行，重复点击不重入。显式单渠道刷新兼容，已发出的请求无法撤回。

冷却规则只匹配实际 Relay 上游失败，关键词检查有界错误消息；正常输出、prompt、客户端取消和模型列表探测不触发。模型级按该渠道的实际上游模型跨 Key/授权/分组共享，渠道级覆盖整个渠道；多来源取较晚截止。等待释放并发额度，原成员解除操作不清除共享规则。配置持久化，运行倒计时仅在进程内、重启清空；规则或出站连接/凭据变化使旧状态失效，展示名称、分类、成功或模型刷新不提前解除。

分类和归属保存在服务端；分类筛选与折叠为浏览器偏好。分类变化只影响展示，保持路由、失败计数、成员顺序、手动选择及冷却状态。

## 日志与排障

请求状态：`running` 表示选路、排队或请求中；`committed` 表示首字节已交付，此后不能重试；`success` 为完整交付；`failed` 为失败结束；`canceled` 为客户端取消。渠道状态另分 `waiting`、`normal`、`error`。请求中日志置顶，筛选影响展示，不更改执行状态；SSE 断线后重新连接并刷新状态。

| 现象 | 检查与处理 |
| --- | --- |
| 刷新时 Key 失败 | 展开渠道刷新详情，检查该 Key、供应商地址和协议路径；旧模型保留。不要通过重复提交覆盖正在运行的刷新。 |
| 模型变为空 | 区分成功空结果与请求失败；检查全局/渠道正则过滤和供应商权限。补齐模型授权后重新同步已有分组。 |
| 请求并发排队 | 查看渠道占用/等待数；流式请求直到结束才释放额度。检查长流或取消情况，再按供应商额度调整上限。 |
| 规则冷却仍未结束 | 查看命中规则、实际模型/渠道范围及剩余时间；多个来源取较晚截止。成功、模型刷新及“解除成员冷却”不清除共享规则状态。 |
| Webhook 失败 | 使用测试发送检查 URL、认证头、超时与目标端状态；v0.1.1 的通知错误保留原值，发送失败仍只报告原有固定分类和状态码。失败阈值通知与恢复通知各自去重。 |
| 备份口令错误或文件损坏 | 核对该文件的口令，含首尾空格；使用未修改的原文件。不能通过改变格式字段恢复。 |
| 导入后已有配置未变化 | 属增量冲突规则。完整替换/回滚使用隔离恢复或数据库副本。 |
| 隐藏的禁用渠道找不到 | 在渠道筛选中切到“全部”或“禁用”；筛选不删除渠道，也不改变备份内容。 |

加密容器机制见[加密设计](backup-encryption-design.md)；本版内容字段和迁移边界以本页及 [v0.1.1 说明](releases/v0.1.1.md)为准。个别渠道的 Anthropic 模型探测告警见 [BUG-001](known-bugs.md)，本版不增加该鉴权回退。
